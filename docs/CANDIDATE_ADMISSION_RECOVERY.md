# 候选准入、有限启用与撤回后恢复合同 v1

2026-09-28冻结。当前裁决：**NO_GO_NO_QUALIFIED_CANDIDATE**。
这是基于现有源码和归档的治理合同，不是市场新研究或运行时授权实现。
[机器合同](contracts/candidate_admission_recovery_v1.json)不被交易进程加载，
不签发权限、不清除日志、不改变既有配置；通过一致性检查也不代表业务GO。

## 一条路径，六个独立关口

| 关口 | 需要什么 | 缺失或失败后的动作 |
| --- | --- | --- |
| G0 研究进入 | 事前假设、可知输入、有限预算/次数、否定出口；关闭路线须有改变原裁决的新材料和单独范围决定 | 不抓数、不回测、不训练；工程PASS和改名不是再入依据 |
| G1 离线候选 | 具名候选、用途/场所/特征/数据版本、成本后独立留出证据、原路线治理与独立回放 | 不准备真实激活事务；缺证为NO_GO，不先跑canary“补资格” |
| G2 有限启用 | G1通过，且有绑定身份/额度/期限的真实启用批准、全组合安全保护与运行前检查 | 不启用；发布代码、CLEAR或Web配置审批不能替代本批准 |
| G3 canary提交 | 原事务样本/收益置信下界/机制/身份/安全证据同时通过 | 按原规则pending或rollback；安全拒绝在当前事务保持 |
| G4 孵化/扩权 | 原孵化全部并列要求满足，并证明样本属于获批候选与获批观察期 | 仅形成复核输入；不自动转实盘/扩大额度，不靠时间或人为更新次数凑通过 |
| G5 撤回后恢复 | 原因、修复、重新资格、明确恢复批准及安全恢复执行协议全部具备 | **当前无恢复执行协议，保持撤回**；修复代码不等于允许解锁 |

G0允许的是研究，不要求先有真实成交或完整账户资格；G1允许的是候选复核，
不能将G3的30次真实episode反过来当G0/G1研究进入条件。阶段之间不循环举证。

## G1：路线不能互相借资格

- **legacy_integrator**：保留`model_registry.py`的Bybit linear/trade_price/base_asset、
  closed_ohlcv、特征同源、原始bar切分/非重叠OOS、成本后指标与置信下界、governance、
  回放/benchmark/objective/feature parity/alpha probe等实际启用分支门槛。
  完整要求以冻结源码为准，不能只取AUC或平均收益。TEST_ONLY产物不是市场候选。
- **microstructure_demo**：按自己的lifecycle、selection/holdout/raw replay与binding
  规则判断；`select_alpha_source.py`的固定优先级只选已独立过关的路线，
  不跨源比较收益或将legacy报告移植过来。demo_ready并不是live资格。
- **option及已关闭研究**：保留`option_candidate_closure_v1.json`的CLOSED，
  `reopening_allowed=false`及`new_identity_alone_permits_reopening=false`。
  C2 `NOT_QUALIFIED`仅能说明该证据体系不合格，不能被当成所有新研究必须先补齐的总门槛。

当前归档没有合格候选。具体否定/缺证对象见[本轮裁决](reviews/2026-09-28-candidate-governance-result.md)。
这里只复核已知材料，不声称今天穷尽了所有外部策略或所有供应商。

## G2：真正启用前必须填写的记录

启用记录至少包含以下项目；当前全部未签发，不用现有yaml默认值代填批准：

1. `candidate_id`、路线、原假设/版本及经济证据包摘要；不是给失败合同换名字。
2. 模型/报告/特征/数据、配置、二进制、release与审批合同摘要；
   实际启动后的boot必须在首次放行风险前与运行证据绑定，不能在启动前伪造boot。
3. Bybit Demo环境和非敏感账户别名；不在公开库保存密钥或账户金额。
4. 单笔/总名义敞口、亏损额度、回撤上限、允许品种/方向/并发订单、账户共享边界。
   **数值尚未决定**；旧策略8%/12%/20%研究线、孵化5%要求不是本次风险授权。
5. 批准者身份、真实批准记录的引用/摘要、适用操作、生效/截止时刻、允许观察范围。
   执行助手可准备材料、验证和执行已批准范围，不能给自己造批准者或替用户设置额度。
6. 本进程组合独立安全撤回已按审批配置启用、日志路径/属主/持久存储身份确定，
   账户/委托/仓位对账与保护状态已通过，停止和模型回滚责任人明确。
7. 观察频率、允许的证据最大年龄、时钟起点与身份更新规则均预先约定；
   过期、未知、冲突即不放行。当前没有凭空选择一个新的年龄上限。

所有批准只能覆盖具体范围；既有main/CI/CD授权不包含这些交易决定。
风险额度/主体/有效期未定之前，不应为了填写这张表先启动服务或转移账户。

## 已由代码执行的规则与未实现的部分

| 条目 | 现有事实 | 本合同的准确边界 |
| --- | --- | --- |
| 初始注册激活 | 注册器验经济/回放等，并检查prepared事务、run_id、policy hash及previous快照 | 不是完整的具名风险批准验证器；不能把prepared解释为G2授权 |
| 最终commit | 事务评估绑定模型/配置/二进制/boot、原收益门槛及显式安全证据；安全拒绝不能自动清除 | 上一工程批次已交付；不宣称覆盖所有路线的初始启用入口 |
| 组合安全撤回 | 应用/入队/发送与持久化锁存保护整个共享净持仓进程；现有profile未开启新触发器 | 新候选真实启用前须单独核对启用及现场状态；CLEAR不证明触发器已开启 |
| Web配置治理 | 有配置草稿、摘要确认及高风险审批逻辑 | 对象是配置发布，不等于候选资格、账户风险授权或解除组合锁 |
| 孵化归档 | 代际键包含release/config/execution policy/incubation policy/environment | **没有直接包含候选ID/模型hash/本次批准ID**，不能直接将一代累计时间当具名候选获批观察期 |
| 恢复 | 没有clear/unlock API；回滚模型不清除安全日志 | 当前G5必须拒绝。没有新增或暗示删文件、换数据目录、重启绕过的方法 |

G2统一批准核验、候选级孵化绑定及G5安全恢复执行协议是具名实施缺口。
本批不悄悄实现恢复、更不以修改批准文件授予交易权；实际启用前必须解决所需缺口。
由于当前G1已经NO_GO，不为不存在的候选先做整套审批系统或恢复执行器。

## 时钟、样本和自学习的边界

- canary当前默认30个完整episode、正收益比例至少0.50、episode净收益/成交均值
  的95%下界严格大于0，机制及其他硬门槛同时满足；参数按事务policy hash冻结。
  默认72小时从事务`created_at_utc`计算，**不是部署成功后重新计时，也不是必须等满**。
- 孵化当前要求至少336小时、14次观测、7个不同交易日、100个完整closed lot，
  以及全部收益/账户/风险/学习/恢复检查（见原policy）；不得只摘其中两个指标。
  代码的小时数是同代账户样本首末时间差，不是`now - 批准时间`。
  新候选以后必须另证候选/批准边界，不能用过去样本填满计时。
- 学习模块可以在**已批准身份和风险范围内**按已有算法评估/冻结/撤回；
  评估频率不等于调权频率，安全动作不等于统计优胜模型的选优。
  有效更新次数是证据，不得为满足孵化门槛强制调权或跳过留出约束。
- 新训练模型、换数据源/假设/风险预算或恢复风险，不属于自动“自学习”放行。
  必须重新完成适用关口；旧样本、旧批准和当前事务安全拒绝不能自动继承为新资格。

## G5：恢复材料齐备也不直接执行解锁

需要保留撤回事件、journal与失败窗口hash、所有已批准身份和变更时间；查清原因，
完成修复及回归；证明在途订单、迟到成交、仓位和保护状态已对账；再完成G1/G2。
另外必须有可审计、单写者、抗崩溃/重放、一次性且绑定撤回事件的新恢复协议，
并证明旧拒绝不能因恢复失败而丢失。**当前协议未实现，因此即使前述材料齐备也不恢复。**
禁止把模型回滚、冷却到期、账户盈利、关闭新开关或重启当作恢复授权。

## 当前推进节奏：事件驱动，不安排空等

本批合同与现有证据裁决一次完成并docs-only交付后结案，不追加技术发布。
当前没有等待验证中的候选，不设置两周提醒或常驻研究任务。

下一实质输入是一份**具名且有新证据的候选提案**：原机制及为何不同于已关闭路径、
事前可知数据、独立成本后依据、可复用证据位置、剩余缺口、固定研究预算和否定出口。
收到后先做G0/G1裁决；仅修复已批准范围内的问题可自动继续，否定/无新证据即停止。
若仍无此输入，结论就是“工程平台已交付，盈利策略研发暂停”，不自动换第四条路线。
后续新研究、实际启用额度、真实恢复是实质决定；普通测试/提交不是新的授权点。
