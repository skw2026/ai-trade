# 自适应组合的独立安全撤回

这是风险处置，不是盈利资格、模型晋升或恢复旧权重。默认关闭新触发器；
现有 `config/` profile 本批不改。已存在的锁存不受开关关闭影响。

## 触发与作用域

`self_evolution.safety_withdrawal_enabled: true` 且学习已启用时，按现有评估周期，
对三个 regime 桶分别记录独立窗口。任一桶连续 `rollback_degrade_windows`
个窗口的所选 PNL 为负、objective 不高于 `rollback_degrade_threshold_score`，
触发 `EVOLUTION_SAFETY_WITHDRAWAL_LATCHED`。所选 PNL 沿用 `use_virtual_pnl`；
虚拟账并非交易所成交。无观测、零收益或非退化窗口中断连续损失计数。

安全窗口不依赖统计选桶，不复用未清空的旧窗口重复计数；样本不足、没有相对
改善、留出拒绝、学习冷却均不能阻止安全检查。统计选优本身的原门槛保持。

锁存同时冻结调权、禁止本进程组合的非 reduce-only 委托。策略输出、应用入队、
异步发送三处设防；同事件探测单重报价在检查之后。已有减仓、SL、TP 和硬风控
保留，不恢复可能加仓的基线。当前没有可靠独立子仓，故明确保护共享净持仓的
整个进程组合；不冒充单候选隔离，也不改变交易所账户设置或其他进程。

## 在途请求与持久化

实际发送与锁存完成有串行边界；已进入交易所请求的订单仍可能成交，不承诺
原子“零新增成交”。对本进程 OMS 中未终结的加仓单发起一次即时撤单；失败保留
真实 OMS 状态并交由既有对账处理，不紧循环重发，不把 REST 受理当成最终消失。
迟到成交继续进入账务、减仓和保护处理。

`data_path/evolution_safety_v1.journal` 为独立、单写者、同步追加的日志：

- `ARMED`：允许风险之前写入；首次创建还同步目录。
- `WITHDRAWN`：永久锁存；内存先关闭风险，即使写盘失败也不能重新下单。
- `CLEAN`：仅正常、未锁存退出后写入。异常退出留下 ARMED，重启保守锁存。

截断、损坏、未知记录、过大日志均锁存；无法读取/锁定则阻止启动。更换配置、
二进制、桶或等待冷却不解除。日志需要持续保留在同一受保护数据目录；本机制
不防御管理员删除整个状态目录，不提供删文件恢复的操作建议。

## 恢复与验证范围

没有 clear/unlock API，没有自动重新晋升。恢复是后续独立治理动作，必须先满足
原市场/候选资格及恢复审核；当前 `NO_QUALIFIED_CANDIDATE` 不变。
可在 `RUNTIME_STATUS` 查看 `evolution_safety_withdrawn`。

### 晋升拒绝联动（2026-09-24）

每条运行快照同时输出 `evolution_safety_identity`，绑定实际配置/二进制摘要及同条
快照的 boot。日志审计从原始输入（平仓重基准之前）提取 `evolution_safety`：
只有显式未撤回、身份完整且一致的窗口为 CLEAR；缺失、畸形、跨身份为 UNPROVEN；
任意撤回/持久化失败事件或 true 快照为 WITHDRAWN。CLEAR 不是市场或交易资格。

激活事务的最终 commit 必须检查该证据并与候选及实际 boot 匹配。安全证据不合格
即 rollback 决策，且在该事务记录重新资格要求；后续盈利、正常报告或重启评估器
不能自动抹掉拒绝。模型回滚不清除进程安全日志，减仓/保护行为保持。本联动不是
自动恢复、初始候选审批或真实 canary 的授权；不新增 unlock/clear API。

保护状态与晋升资格分别报告：安全锁生效本身不等于保护机制损坏。因此旧日志仍
可用于原工程诊断，但没有新安全证据就不能作为晋升 commit 的依据。

CTest 的 `evolution_safety_test` 覆盖真实生产应用/控制器/执行器/持久化组合，
`evolution_safety_audit_test` 覆盖审计器负例。CD 原固定学习回归额外用同一实际
训练模型跑正常、退化、短窗口控制；逐窗口虚拟账独立复算，失败阻止部署。
这些都是 TEST_ONLY 合成证据，不证明当前线上开关已启用、真实盈利或完整生产
自学习目标完成。独立安全撤回的恢复机制有意不自动开放。
