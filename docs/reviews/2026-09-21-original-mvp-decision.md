## 1. 历史查重：不能把它当成从未测过，也不能用旧 PASS 放行

检查范围为本地当前源码/配置、可读的 Git 历史、阶段报告和现存回放 JSON；未访问账户或远端私有原始归档。不能声称穷尽所有历史实验。

- 4–5 月已有趋势片段回放、固定 corpus、成本及覆盖优化。当前 `latest/replay_validation_report.json` 的对象是 BTC、`target_bucket=trend`、`bybit.replay.assess.yaml`；实际仅一段 **54 根 5m bar**，1 次成交，汇总 `fail`（要求至少 3 个活动/通过运行及 3 次成交）。不是连续季度、多币种、全市场状态的原 MVP 经济验收。
- `corpus_smoke` 与 `corpus_smoke_reuse` 都只运行一段后因最低覆盖满足提前结束；门槛为 1 个活动运行/1 个通过运行/1 次成交，单笔净值最低值 `-0.005`。它们的 `pass` 不能升级为全成本正收益或完整生命周期通过。
- 现有 replay/assess 配置含 `defensive_notional_ratio=0.30`、regime 分桶、趋势过滤和自适应费用门槛，不等于原 PRD 的纯趋势 MVP；仅把文件重命名为 baseline 不能消除这些差异。
- 旧 closed-loop 的模型 AUC/IC、注册与执行 PASS 和 `backtest_walkforward.py` 的训练型 benchmark，也不能当成同一个固定原 MVP。H1 是周频固定名义合同，已按原规则拒绝，不拿它的失败调仓补救。

因此，**没有据此确认“原 MVP 已被同口径否定”，也没有确认“原 MVP 完全没测过”**。即使另有完整旧报告，下面当前实现的合同差异仍需独立处理。三个本地回放报告的 SHA256 已记录；其旧构建身份未在本轮重认证。

## 2. 三处决定性差异及复现

原需求：[5m 主信号、趋势+VolTarget、8/12/20 风险动作与恢复](../需求描述.md)。当前源码及合成观察的完整身份见[机器证据](2026-09-21-original-mvp-contract.evidence.json)。全部金额/价格均为人工测试数，不来自真实账户。

### A. 基础趋势信号时钟未绑定为 5m

`StrategyEngine::SymbolState` 以 `OnlineFeatureEngine{100}` 初始化，没有指定 bar interval；默认 interval 为 0，ticker 会直接成为一个样本。`OnMarket` 每条行情先更新特征，再计算 EMA(12/26)。因此喂入秒级 tick 和 5m OHLC 时，“12/26”对应的实际周期不同。Regime 或 Integrator 自己的聚合不能自动修复这个基础策略时钟；`feature_only` 事件也只进入 Integrator。

合成观察：60 个 5 秒 tick，跨度 **295 秒**，两个配置都已进行 **59 次趋势计算**。**本例没有非零方向信号**，不声称发生了盘中下单；这是样本时钟核对，不是交易活跃度或盈利测试。源码中的逐事件入样本才是周期不一致的直接证据。

参考：`src/strategy/strategy_engine.h:62`、`src/strategy/strategy_engine.cpp:128`、`src/research/online_feature_engine.cpp:433`、`src/app/bot_app.cpp:4850`。

### B. 普通 taker 回放没有“一根 bar 之后才成交”的语义

[闭环合同](../闭环收敛契约.md)要求 `execution_latency_bars >= 1`，禁止用本根收盘后完整特征在同一收盘价成交。但 replay 的普通 taker 分支直接以 intent price 入成交队列；真正等待后续 OHLC 的是 maker/条件单分支。成本加点并不能替代因果延迟。

合成观察：用本根收盘 **101** 形成趋势信号和订单，尚未调用下一次 `PollMarket`，已收到 **2 个部分成交**，合计 VWAP **101.0101**（单侧 1 bps 滑点）。这是一个订单的拆分，不是两个独立交易。maker 对照在下一事件前为 0，下一事件后为 2。

`run_replay_validation.py` 写出的经济合同统一标记 `next_bar_ohlc_first_touch_v1`，但不能据此推定上述 taker 分支也满足它。这是声明与实际执行分支的差异，不能用报告字段名证明通过。

参考：`src/exchange/bybit_exchange_adapter.cpp:2200`、`src/execution/execution_engine.cpp:130`、`tools/run_replay_validation.py:3749`。

### C. 风险保护会生效，但全平后的恢复合同缺失

`RiskEngine` 在 DD>=12% / >=20% 将目标归零，恢复依赖 DD 自身下降到回撤滞回线以下。`AccountState` 按历史峰值计算 DD。全平且没有外部收支时，价格变化不再改变权益，DD 也不会下降；单纯延长等待不能退出锁存。

合成观察：分别制造 **13% / 21%** 损失并全平，继续推进 **2016 个 5m 时刻（合成一周）**，仍分别为 `COOLDOWN / FUSE`，非零恢复目标都是 0。有限运行加上述状态方程证明的是这些固定条件下的闭环问题，不是实际账户损失概率。

**安全锁存本身不应被直接删除。** 12% 后全平是现实现的保守动作；PRD 明确要求 20% 熔断后的分段恢复，但没有在这里绑定恢复授权、期限、预算及回撤基准。既不能靠修改 8/12/20 阈值“通过”，也不能偷偷重置峰值、注资或重启使 DD 消失。

现有风险单测通过人工传入已下降的 DD 验证滞回切换，不代表一个已空仓的封闭账户能自行达到该条件。运行中远端风险刷新明确不重置峰值，不能拿它当自动恢复路径。

参考：`src/risk/risk_engine.cpp:16`、`:75`；`src/oms/account_state.cpp:107`；`tests/test_trade_system.cpp:7267`；`src/app/bot_app.cpp:4812`。

## 3. 为什么不是继续下载数据或立刻改三行代码

最早失效环节是**目标—运行策略—模拟成交—生命周期没有绑定成同一合同**，在行情数据之前。历史长度不能修复信号周期和同根成交；等待不能让空仓账户降低 DD。旧工程通过主要证明特定模块/对账/回放确定性，不能覆盖缺失的端到端经济对象。

按三个视角复核（同一次审查，不虚构独立参会人）：

- **需求视角：** 基础趋势、MVP 以外的防御/自适应逻辑和外部研究假设不断混用，导致“正在验收哪一个对象”漂移。当前应停止换路线。
- **工程视角：** 5m 信号与秒级风险可分离，下一事件成交可以实现；但会改变当前模拟路径，必须有针对反例的测试，不能先跑收益再选实现。
- **经济视角：** 即使修完，也只能重新获得一次可解释的筛查能力，不能推出盈利。风险恢复规则影响资本曲线与样本占用，必须事前固定，不得看结果后补。

对“为什么几个月仍没收口”的可证实回答：**过去多个局部验证验的是不同对象，且新机制/新证据不断接续；这次在原目标的前置行为核对中就失败了。** 不能将全部历史损失归因于这三点，也不能宣称修复后必然收敛盈利；它们已足以否定“现在直接补行情跑原 MVP”的路径。

## 4. 下一步应怎样做（改造提案，未自动授权执行）

不再提新的 alpha 路线，也不安排两周等待。如果用户决定继续投入，应先批准**同一原 MVP 的最小合同改造**，而非又批准一轮候选搜寻：

| 顺序 | 具体交付 | 放行条件 |
|---|---|---|
| 1. 先定风险生命周期 | 明确熔断后是人工授权新风险周期，还是有条件自动恢复；固定冷却时钟、分段预算、再熔断规则与回撤口径。永久保留全生命周期损失/高水位证据，禁止隐藏回撤。 | 规则可由合成路径验证；若所选规则改变原风险验收，必须显式批准，不能开发者自选 |
| 2. 统一信号与成交时钟 | 基础策略只消费同一套已收盘 5m bar；秒级事件只驱动风控/执行。taker 决策与成交事件分离，下一可执行价格计入成本，末端结算独立标识。固定关闭哪些阶段2分支，不调 EMA/收益参数。 | 同一已闭合 OHLC 的不同 tick 切分产生同一策略输出；篡改未来价格不影响过去信号；生成信号的 bar 不可能完成该信号成交；费用/funding/终值仍可对账 |
| 3. 一次合同验收后才评估是否恢复历史筛查 | 将当前三个合成反例变成正向验收，绑定唯一配置/代码/hash、连续数据区间和成本/退出口径，再使用未消耗的单次历史额度 | 不降低原标准；任一失败先复盘且不补采/换参数。通过仅允许历史筛查，不允许 Demo/发布 |

建议这项**后续工程改造本身最多 4 个有效工程小时**，若风险合同无法确定或行为验收不通过就停止；这是待批准的限额，不是本轮预算自动续期。当前不会自行开启这项工作。
