## 延迟失败的实锤原因

本次延迟合同规定：用实际上一目标计算新信号，同时执行上一bar排队的
旧目标。这在有“空仓入场门槛、已有仓位保持”语义的策略中形成反馈振荡。
原始轨迹中的首次事件如下，目标单位是参考名义金额：

| UTC | 决策前实际目标 | 本bar执行的旧队列 | 新算出的目标 |
| --- | ---: | ---: | ---: |
| 1月3日12:10 | 0 | 0 | +2,500 |
| 1月3日12:15 | 0 | +2,500 | 0 |
| 1月3日12:20 | +2,500 | 0 | +2,500 |
| 1月3日12:25 | 0 | +2,500 | 0 |
| 1月3日12:30 | +2,500 | 0 | +2,500 |

12:10评分均值约0.001503足以开多；随后约0.001069、0.001022，低于空仓
入场门槛，但对已有多仓仍应保持。由于新动作读取执行前的实际状态，
上一笔待执行入场尚未体现在状态里，立即产生排队平仓；平仓执行前又产生
排队持仓。之后反复振荡，直到硬停止。

独立只读诊断核对了全部队列转换。120段持仓全部仅一根bar，240次成交；
压力手续费、滑点和资金费占压力净亏损99.73695%。不用任何市场价格或
损益账，仅“首次强信号、随后恒定弱正信号”的代数反例，也会产生
`0 → 多 → 空 → 多 → 空 → 多`的执行序列。因此队列反馈是已证实的结构
问题，不是猜测接口延迟或通过重跑成功推定根因。

责任边界也要明确：这是本轮新延迟建模的设计缺陷／解释限制，不能扩大为
已经证明线上系统存在同一缺陷。实现和Decimal审计一致，只证明忠实执行
冻结规则，不证明规则适合作为“纯成交时点延后”的隔离实验。事前合成测试
覆盖了账务、风险、队列时序，却没有把“恒定保持信号不得自激开平仓”列为
设计验收不变量，这也是本轮准备不足。当前没有修该规则或重算利润。

1. 先冻结三类状态及更新顺序：策略意图不随待执行动作在实际仓位中的
   滞后来回翻转；风险由实际持仓决定并优先取消待执行增仓。用恒定信号、
   单次反转、资金费触线、终点取消检验“不自激换手”。设计不一致即停止。
2. 把“纯执行延迟”与“带反馈的在线策略”分成不同问题。前者可以只对本次
   已冻结正常动作序列延后一根bar，核成本／风险，明确这是固定动作反事实，
   不是证明真实闭环；后者必须先定义pending-aware决策契约，不能借前者通过。
3. 设计和合成检查先通过，才在新范围内允许最多一条基础／压力配对的固定
   动作延迟验证。复用本次正常账，不重跑原对照或再选参数；结果无论正负
   都结案。该新经济次数不属于本批，不能自动执行或把本次失败改绿。

预计交付是明确的“纯执行时点是否保留净收益”判断及状态契约，仍不是

完整开发支持和可承担的独立出口同时明确，才讨论下一确认阶段。
