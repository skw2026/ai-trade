## 已完成的实现

1. [原始响应提取器](../../tools/audit_c2_rest_anchors.py)只读既有 V4 归档和固定 ledger。验证选中分段的压缩文件 SHA、报告合同、行数与快照身份，并要求整个目标生命周期仍为 **1,179 个快照、canonical SHA `3bad663f05b17753a6dbb7c32c064783550c8215b89c8cb4c18a1fcd4999e17c`**；不能只找两条看起来合适的报价。两个响应须同时匹配 ledger 的 bid/ask 价格、数量及因果事件时间。缺失的 `cts/u/seq` 明确报告，不补零、不推算。
2. [离线对齐器](../../tools/audit_c2_rest_depth_alignment.py)复用已下载并重放的固定 ZIP，绑定原 REST 报告、前次深度证据及完整 ZIP/member SHA，读至 EOF 验证 CRC。分别按 publication `ts`、matching-engine `cts`、cross sequence 建立两侧观察；重新核对前次重建的先行盘口身份。没有新下载器、交易接口或回填旧账逻辑。
3. 分类出口包括：缺元数据、序列在两个更新之间、序列超出覆盖、序列/引擎时间冲突、同序列同引擎时间但晚发布、同状态候选仍需完整深度检查。**任何一个分类都不直接签发历史资格或实际成交证明**。同序列不等于完整盘口验证，未来发布时间只作诊断。
4. [研究工作流](../../.github/workflows/c2-rest-anchors.yml)最终改为手动触发，普通提交不会反复访问未改变的阻塞源。缺少可信主机指纹时，在扫描主机或传输文件之前停止。传输和取证使用同一组严格 SSH 参数，只信任与指定指纹匹配的公钥，而不是扫描返回的全部公钥。

字段语义按 [Bybit REST 文档](https://bybit-exchange.github.io/docs/v5/market/orderbook)与 [WebSocket 文档](https://bybit-exchange.github.io/docs/v5/websocket/public/orderbook)区分：REST `u` 不与 ob200 `u` 直接比较；`seq` 差值不是漏包数量。未把 REST 的系统发布时间误称撮合时间。

## 唯一需要用户补充的当前取证配置

请通过 **ECS 控制台或已可信的运维连接**获取 SSH 主机公钥指纹，例如在服务器控制台执行：

```sh
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256
```

将输出中的 `SHA256:…` 指纹配置为 GitHub 仓库 **Settings → Secrets and variables → Actions → Variables → `ECS_HOST_FINGERPRINT`**。也支持同名 Secret，但 Secret 优先；已有值冲突时先核对，不盲目覆盖。不要把无独立验证的 `ssh-keyscan` 输出直接当可信基准，不要提交私钥或交易 API 密钥。指纹不是 SSH 登录公钥或账户 API key。

配置确认后手动运行 **C2 Archived REST Anchors**。它只读取已指定的 V4 公共市场归档与固定 ledger，最多发布两条报价及来源摘要，不查询交易账户、不切换 Demo 模式、不下单。此配置只解除运输预检，不保证源校验通过，更不等于 C2 合格。
