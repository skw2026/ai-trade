## 4. 圆桌交叉质询

### 金融机制：否定的是收益机制，还是某个实现？

质询：当前 short 跨式、离散 Delta 对冲和成本之后的收益，是否已经证明“波动风险溢价不存在”？

反方：没有。此收益混合了期权定价、实现波动、跳跃、对冲离散误差和交易成本。六期摘要没有告诉我们到底哪一项主导失败；本候选也不是包含所有期限、场所、风险预算的机制上界。

裁决：停止当前冻结动作的晋级，有充分治理理由；对整个 VRP 做全面否定或立即改做 long，没有足够证据。下一步必须先分清“gross 本就不足”“执行成本吃掉优势”“账务缺项”“资本/尾部不可接受”，不能预先把失败归咎于手续费或模型弱。

### 会计与执行：现在的 net 是什么？

[payoff v3 的 `_action_result`](../../tools/audit_option_lifecycle_payoff_v3.py)由 V4 复用，计算：

```text
base_net = option_and_hedge_gross
           - option_spread - option_fee - delivery_fee
           - hedge_spread - hedge_fee
stress_net = base_net - frozen_stress_increment
bps = net / (entry_index_price × quantity_per_leg) × 10000
```

永续实际 funding 不在该式中；名义分母不是实际账户净值或保证金资本。真实 funding 可能支付也可能收入，必须绑定结算时刻持仓、mark 和已结算费率，不能填 0 或用当前预测值代替。[Bybit 资金费说明](https://www.bybit.com/en/help-center/article/Funding-fee-calculation)

反方：是不是“发现收费错误，修掉即可扭亏”？

不是。[payoff v2](../../config/option_lifecycle_payoff_v2.json)明确将日度期权交割费定义为保守标准费率，而非交易所豁免；这是已知冻结假设，不是本轮新发现的程序 bug。官方确实列出日度期权免交割费，但逐合约实际适用规则仍须核对。新账务应并列保留实际费用与保守压力费用，不能为了翻转 STOP 原地删除旧扣款。[Bybit 期权费用说明](https://www.bybit.com/en/help-center/article/Bybit-Option-Fees-Explained)

裁决：旧报告继续称“冻结费用项口径净收益”。完整账户账务应复用 [子账户内核](../../tools/audit_option_subaccount_ledger.py)，补真实事件适配与独立核对；该内核只验证外部保证金快照，并不自动产生已验证的历史保证金模型。

### 计量统计：六期、10,000 次 bootstrap 能证明多少？

质询：代码写 `independent_unit=completed_sticky_lifecycle`，是否等于六个统计独立样本？

反方：不是。按生命周期取样避免把快照冒充样本，但相邻周期可能共享市场状态。当前 `_bootstrap_interval` 是普通有放回重采样，10,000 次是计算次数，不增加真实样本。0.9 配置对应中央 90% percentile 区间，不能说成已经证明总体负期望，更不能推广到所有未来行情。

此外，economic v1 于 **09-08 02:00 UTC** 冻结，首个生命周期已于 **09-07 08:00 UTC** 交割；合同明确是“第二个交割结果前冻结”。聚合仍纳入所有已完成生命周期。因此六期整体属于 development 筛查，不是六个结果全部未见的纯 OOS 检验。

同一批数据的重复检查不会增加样本；新增样本后不断重算并允许 PASS，也不能自动获得跨多次查看仍有效的错误率保证。下一版应事先固定检查点与终止规则；若采用 confidence sequence，必须另行证明收益尾部和依赖假设适用，不能套一个算法名称代替证明。[Howard 等，2021](https://arxiv.org/abs/1810.08240)

裁决：保留六期 STOP 作为资源淘汰记录，不拔高为总体统计定理。旧六期用于诊断；基于它产生的新候选，晋级证据必须来自未用于设计的数据。不得事后剔除亏损期、改 split 或直接挑表现好的对照。

### 数学与风险：能否给出 Sharpe、回撤及最终成功概率？

目前不能。[聚合器](../../tools/audit_option_lifecycle_economics_v1.py)的 `*_max_drawdown_bps` 是按选择顺序累加各期名义 bps 后的回落，不是账户百分比回撤，也看不到期中保证金风险。源码明确禁止 Sharpe、drawdown 和 profitability claim。

下一版必须先定义同币种、剥离外部资金流的账户净值序列，以及超额收益基准、采样频率和风险预算。MDD 应基于完整可用净值路径，并标明观测分辨率；压力损失另报。序列相关会影响 Sharpe 估计与年化，不能机械由六期收益给出“Sharpe 1.5/2.0 可达”。[Lo，2002](https://alo.mit.edu/publications/page/18/)

裁决：最终目标可以是“在已声明资本和尾部约束下寻找正净效用，并在失效时可靠停止”，不能是“保证持续盈利且自我进化单调变好”。当前成功概率、年化收益、账户 Sharpe、MDD 均记为未知；不继承未经批准的目标数字为新运行阈值。

### 工程与治理：STOP 为什么还需要人工解释？

`audit_option_lifecycle_economics_v1.py` 每次聚合全部完成样本，不读取前次决策，也不锁存 STOP；工作流仍接受合法的后续 PASS。这是无状态批量审计与候选治理之间的缺口，不应通过修改冻结收益公式来解决。

本轮合成探针复现：六个负值生命周期返回 STOP；在保留这六个负值的模拟聚合输入后追加十二个正值，返回 PASS。该探针对生命周期评估进行了 mock，只证明决策层不记忆 STOP，**不是线上后来出现十八期或利润反转的证据**。

裁决：保留可重算的冻结审计器；在外层增加候选注册与终态锁存。首次 STOP 的 run、artifact、输入身份和合同一并冻结；后续数据可以采集、诊断，但不能自动恢复该候选的晋级资格。新的经济定义必须有新候选身份、变更理由和独立证据，不能仅换名字。

### 项目推进：还要不要继续等？

不需要为了**这个已触发 STOP 的候选**再等 24 小时或 35 天。原始报告取得、账务接通、缺项核验、边界反例、历史经济淘汰都不是只能靠时间解决的工作。

更高效的做法是同一份合格数据一次产出三类结果：数据能否用、账是否完整、经济是否值得继续；计算上可复用输入，逻辑上仍按 R2 → R3 → R4 验收。前向数据只能解决明确的未见事件/迁移问题，不能代替尚未实现的功能。

## 5. 关闭、保留与禁止事项

- **关闭晋级：** 当前冻结 short 候选；不再用延长观察、调整阈值或追加模型挽救原结果。关闭锚点为 run `34685429648`，不是不断变化的 latest。
- **保留资产：** 原始采集和 checksum 链、不可变合同、现有结果、诊断对照、子账户账务内核及测试。未删除数据，也未停止共享采集服务。
- **暂缓：** 新 alpha 搜索、复杂目标架构、自适应启用和交易集成扩建；这些不能修补未验收的目标/现金流。
- **权限不变：** 不创建/切换账户，不划转资金，不启用新 Demo/live。独立子账户设计许可不等于交易许可。
- **不隐瞒未完：** 六期数值归因和运行时关闭锁存未完成，不能称为已完成全部技术与财务关闭。

## 6. 下一阶段：按结果交付，不按天排期

以下是本轮建议采用的执行顺序，尚未实施代码变更。一次只推进一个验收出口，不能用更多模块代替尚未通过的门。

| 顺序 | 交付物 | 验收出口与失败处理 |
|---|---|---|
| C1 关闭证据与治理 | 取得首次 STOP 的三份聚合 JSON，验 ZIP digest；核对六期 ID、合同、release、输入 hash；外层终态锁存及回归 | 原报告缺失则明确证据受限，不生成假账；验证 STOP 后追加正样本也不能自动晋级，旧报告保持可重算 |
| C2 单一真实生命周期贯通 | V4 原始输入 → 有来源的事件 → 实际 funding/费用 → 期权和 hedge 现金流 → NAV；保证金及退出资格单列 | 手算/独立实现对账一致；缺结算 mark、费用来源或 margin 模型则输出精确缺项，不能造数过关；一个生命周期通过仅是集成子项 |
| C3 同六期失败归因 | 不变动作/数量/时序，并列旧冻结成本、真实适用成本、funding 和压力增量；逐期列出 gross/成本/风险贡献 | 能区分账务偏差、经济不足、执行约束或风险不可行；新口径只作诊断，不覆盖旧 STOP，不自动恢复晋级 |
| C4 新候选可行性筛查 | 仅当归因支持具体经济机制时，先定义一个新候选及不交易/固定对照；以合格历史、真实约束做成本与资本淘汰 | 连经济乐观上界都过不了就停止；上界通过也仅是必要条件。缺合格历史则列来源/成本/字段缺口，涉及采购另行审批 |
| C5 冻结后迁移验证 | 只有前述资格成立，才注册新的动作、风险预算、统计检查点、终止规则和未见数据边界 | 此时才等待明确的新完整 lifecycle 或市场事件；满足数据/风险/统计条件才进入 Demo 评审，仍不自动启用 |

C2/C3 的适用费用核对属于金融语义重建，不是调参；如果结果与旧代理相反，应留两套结果和原因，由新证据决定新候选是否值得注册。

出现下列任一情形即再次复盘，而非继续补丁：来源无法支撑结论；账务恒等式只在删除成本后成立；风险未知被当成安全；为 PASS 调低成本/阈值；同一候选经济停止后换名重开。

关于模型的裁决：本阶段不选“更高级模型”。先有可执行净效用标签及简单固定基线，才有资格比较条件机会识别或风险约束动作排序；自适应必须在同资本、同成本、同路径条件下相对 frozen 基线证明增益。六期诊断不能同时用于设计模型和声称模型得到独立验证。
