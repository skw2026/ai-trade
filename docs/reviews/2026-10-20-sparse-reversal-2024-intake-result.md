# 冻结反转2024输入核对 缺少23小时预热

已执行用户接受的[有界迁移计划](../plans/2026-10-20-sparse-reversal-2024.md)
的输入核对。结果为`INPUT_INSUFFICIENT`：2024年内的分钟行情完整，但
冻结模型需要的年初前24小时预热只覆盖1小时。**经济实验没有开始，
不能据此评价2024收益、策略成败或G4。**

## 已核实的边界

| 项目 | 实际结果 |
| --- | --- |
| 冻结模型 | 原`(0,-4)`及SHA一致，没有训练或改参数 |
| 固定评价域 | 2024-01-01至2025-01-01 UTC，右端不含，366日 |
| 评价域所需5分钟bar | 105408根；现有分钟覆盖足以聚合 |
| 模型预热起点 | 2023-12-31 00:00 UTC |
| 现有分钟起点 | 2023-12-31 23:00 UTC，原成交响应首点与审计一致 |
| 缺少预热 | 23小时，即276根5分钟bar |
| 本地替代线索 | 225份相关顶层输入元数据及归档manifest中，没有覆盖缺段的同市场1分钟或5分钟请求线索；0份因过大或解析失败跳过 |
| 原生驱动 | 已有冻结本地二进制存在；本轮未执行市场回放 |

复核了上一批输入审计列出的8份编译产物hash、BTC数组长度、首段原始响应
身份和起点。元数据核对是限定目录范围，不是证明所有磁盘或外部渠道均无
所需数据。已有小时原件不能提供288根5分钟的完整时序，Binance交割/现货
归档也不能替代Bybit线性永续。没有把2024-12-31误当2023-12-31预热。

本地同模型hash检索命中原2021迁移和2025开发，没有定位到可复用的2024
同规则经济结果；不是对所有可能历史运行的全局无使用认证。2024仍已见开发。

## 根因和处理

提案前只确认了全年分钟行情，没有同时核对旧模型的预热要求。这是本次
方案准备遗漏，不是交易接口失败、模型亏损或需要增加学习轮数。接受范围
明确为0新增行情，故未自动补请求，也未删掉首日、改变评价域或插值造数据。

当前已提出一次限额修正：最多2个匿名公开GET，成交和mark各一次，只请求
`[2023-12-31 00:00,2023-12-31 23:00)` UTC的5分钟预热。是否能成功取得且
通过一致性校验尚未验证；不能把补请求建议写成数据已恢复。
原模型、评价年份、成本、风险、8小时总工程预算及唯一经济次数均不扩张。
截至本记录，尚未收到这一修正的明确答复，依赖步骤保持暂停。
