## 具体假设与旧路线差异

假设：两个资产共同市场波动之外的部分相对价格偏离可能修复；对偏贵一腿
做空、偏便宜一腿做多，只有预期修复空间足以覆盖完整成本时才值得交易。
这不是同一资产两市场的价差，也没有到期强制收敛、固定兑付义务或无风险
套利保证。两种资产可以长期分化，相关性高不能推出价格比或残差均值回归。

与已关闭的[SOL现货／永续carry](2026-08-25-funding-basis-carry-result.md)不同，
这里不是赚同币资金费与基差；资金费是每腿实际现金流，不预设净收入。与
旧单币稀疏反转不同，交易对象是两资产联合持仓及其相对价格，不仅是给旧
方向评分增加跨资产特征。仓库范围内关键词检查未找到专门配对交易合同，
但这不是对所有旧实验的“从未使用”认证。

已有[加密配对研究](https://arxiv.org/html/2109.10662)提供可检验的方法线索：
训练期估计关系、交易期评价，而不是先挑全年赢家。但它研究2018—2019年
BitMEX资产，不包含本候选；部分结果的26%—35%利润来自返佣，执行回放使用
买卖报价和成交数据。不能把其收益／夏普搬到Bybit ETH/SOL，或把历史做市
返佣写成本项目收入。本文不复现该论文，也不据其摘要宣布经济可行。

如果未来具备准入条件，最小模型应先是训练期估计并冻结的双腿关系与固定
入退场基线，而不是立即加入深度网络或强化学习。系数只用决策前数据；
持仓中改变系数产生的实际交易必须入账，不能用重估残差抹去亏损。当前
没有冻结数值阈值、选定训练年份或启动学习器。

## 完整退出及实现边界

[官方下单接口](https://bybit-exchange.github.io/docs/v5/order/create-order)
支持reduceOnly，但市价指令按IOC限价保护执行，可能不成交；响应是异步
受理而非成交证明。[批量下单](https://bybit-exchange.github.io/docs/v5/order/batch-place)
分别返回各单创建结果，不应假设两腿原子成交。以下为必要设计，不是已部署
状态机或在目标规模下实测通过的退出保证。

| 中间状态 | 必要处置与完成证据 |
| --- | --- |
| 双腿未成交／存在挂单 | 不重复放大委托；撤单结果未确认前仍保留占用和潜在成交敞口 |
| 一腿成交，另一腿拒绝或超时 | 停止新增；核对两腿实际成交与剩余挂单，以reduceOnly撤回已成敞口，不靠加仓摊平或无限追另一腿 |
| 两腿部分成交、数量不匹配 | 按实际逐腿数量和总名义敞口计风险；未成部分不当作对冲，必要时减仓／退出 |
| 正常持有／关系失效／风险触线 | 取消增加风险的挂单，分别减仓；一腿先平后的残余方向风险继续计账，不等价差回归才止损 |
| 断连／订单结果未知 | 禁止新增；重连后按订单ID、成交和仓位对账，不能以超时当作未成交再发同额新单 |
| 声称全平 | 两腿实际仓位及可能新增敞口的挂单均核实；净名义为零或下单ACK不等于完成 |

相比赎回NFT，这条路径没有协议不可撤销排队状态；但交易所故障、流动性
枯竭、ADL和清算风险仍在，不能承诺任何状态下即时无损退出。

现有[TradeSystem](../../src/system/trade_system.cpp)已经有账户gross notional
限制和离线待成交序列化；不需要再造一套账户总额框架。但
[OrderIntent](../../src/core/types.h)及[适配器](../../src/exchange/bybit_exchange_adapter.cpp)
按单symbol组织意图与请求，不能据此宣称双腿生命周期已经验证。联合持仓、
部分成交撤回及逐腿风险测试是后续工程缺口，不是当前已确认的运行时bug。
本次未修改这些源码，不因候选未准入先建设配对平台。

产品8%降档／12%强制减仓冷却／20%经济全平与研究8%停止分别保持；不把
双腿净敞口接近零当作保证金、总名义或清算风险为零。普通继续不能解除
Demo人工禁开仓。

## 成本口径：四次成交，不能少算一半

[Bybit公开费用表](https://www.bybit.com/en/help-center/article/Trading-Fee-Structure)
列出普通VIP0永续／期货taker为0.0550%；实际费率还依赖地区和账户等级。
本轮未访问账户，这只是公开参考，不是已核实的账户费率或历史费率。

若两腿各名义N、开平四次成交名义均恰好为N，仅按5.5bps参考手续费：

`四笔手续费 = 4 × N × 0.00055 = 22bps × N = 11bps × (2N)`。

例如各1,000 USDT，手续费为2.20 USDT；11bps的分母是2,000 USDT双腿总名义，
不是接近零的净敞口。真实平仓名义随价格变化，必须逐笔计算；资本收益还需
另用实际初始权益分母。以上仅Decimal算术核对，不是策略成本后收益。

完整账应为逐腿价格损益，加实际资金费现金流，减每笔成交费与执行损耗。
若价格已采用真实bid/ask成交价，不能再重复扣同一spread；以中间价做参考时，
则必须显式扣除价差、滑点和腿间延迟损耗。失败建仓后的撤回交易也须计费。
不预设两腿资金费相消、不凭收益结果反推低费率、不假设必定maker成交。

[历史K线](https://bybit-exchange.github.io/docs/v5/market/kline)及
[资金费记录](https://bybit-exchange.github.io/docs/v5/market/history-fund-rate)
有官方字段定义；资金费必须按每腿实际结算时点与实际持仓记账。
[orderbook接口](https://bybit-exchange.github.io/docs/v5/market/orderbook)是当前
快照，不提供该接口的历史时间查询。OHLC不能还原同期两腿深度、成交顺序
或全部部分成交状态。未绑定历史执行资料与规模压力假设前，只能讨论参考
回测，不能承诺真实执行可复现；当前也没有完成两币行情的实际可达性检查。

## 多视角复盘与下一动作

金融判断：退出结构比协议赎回贴近现产品，但没有强制收敛或成本后收益证据。
计量判断：联合关系需要实测，历史选择偏差及确认容量不能靠复杂模型解决。
执行判断：双腿非原子、总敞口和失败撤回不能省略；现框架可复用但未验证。
交付判断：当前硬约束的交集尚没有可执行到G4的完整计划，不能先开发再追加
未获约定的长期等待。这是目标与可用证据之间的缺口，不是又一个待打补丁的bug。

因此在G0停止依赖步骤：不下载全年行情、不训练、不新增配对执行器、不自动
换第二候选。重新接续的实质输入应是可认证的独立历史输入，或事前明确的
冻结前瞻方案及其日历／运维上限；改变统计验收则属于方法与目标范围决定，
不能在看过结果后放宽。未出现上述新输入／决定，不继续同类文档或检索延长
投入。这里没有默认购买数据、默认半年观察或必须升级API套餐的建议。
