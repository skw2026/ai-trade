## 三、多角色质询与结论

### 1. 产品与交付负责人

质询：当前项目的“可交付结果”是什么，是否应该直接寻找下一策略？

结论：当前可交付结果不是一个收益候选，而是一个**可信地接受或拒绝真实生命周期输入的账务资格链**。旧候选已经退出晋级队列，新候选还没有完整标签和资本约束；此时转向模型或策略搜索会在错误目标上扩大投入。交付顺序必须保持 C2 → C3 → C4 → C5。

### 2. 量化研究与金融机制

质询：gross 五期为正、累计为正，是否足以主张只需优化手续费或降低对冲频率？

结论：不足。当前证据只支持“对冲周转/费用是主要已列拖累，值得作为一个待证伪机制”，不支持“降低对冲一定提高净收益”。减少对冲会改变 gross、Gamma/Delta 暴露、跳跃损失、保证金和尾部；必须用同一路径、同资本和完整账务重新评估。旧候选不能因此重开。

### 3. 计量经济与统计审查

质询：六个生命周期和 bootstrap 上界是否已经证明总体负期望，或者足以估计 Sharpe/MDD？

结论：都不足。六期共享市场状态，重复审计不产生新样本；现有 bootstrap 是对冻结六期的诊断，不是独立 OOS 试验。没有连续账户 NAV、资本定义和跨状态未见样本时，不报告账户年化收益、Sharpe、MDD 或成功概率。新候选必须在看结果前固定假设、动作、成本、资本、未见区间、检查点和停止规则。

### 4. 会计、风险与资本

质询：现有离线 ledger 是否已经解决资金费和保证金问题？

结论：内核解决了**如何验证输入和拒绝缺项**，没有凭空提供真实输入。C2 仍至少需要：

- 首期每个 funding 边界的有符号持仓、适用 rate 和结算 mark，或经批准且有误差边界的研究替代模型；
- 绑定历史版本和产品/账户模式的期权、永续、交割及 funding 费用；
- 普通 Cross 下的初始/维持保证金、订单占用及至少一个独立对账样例；
- 持有期余额、未实现期权负债、保守退出价值和保证金余量形成的 NAV 路径。

任何一项缺失都应输出 `INSUFFICIENT_EVIDENCE`，不能用零、测试常量或当前接口值补齐历史事实。

### 5. 数据与证据工程

质询：是否应立即采购多年 tick 数据以缩短等待？

结论：现在不批准广泛采购。先读取部署环境已有 raw，产出首期 adapter report；只有报告证明现有归档缺少不可替代字段时，才提出“首期、三个 funding 边界、明确合约、明确字段、明确时间窗”的最小样本或报价。供应商覆盖说明不是字段资格，采购仍是用户独立批准点。

### 6. 工程与 SRE

质询：本次代码是否具备提交条件，部署后第一项动作是什么？

结论：本地 warnings-as-errors 构建和 79/79 CTest 已通过，适配器对篡改、缺文件、交割后行情、L1 深度不足和覆盖输出均失败关闭，具备代码提交条件。提交本身不等于部署；部署后第一项动作是在持有 raw 的环境只读运行适配器，保留输入/输出 SHA256 和程序退出状态，不触碰账户或发单链。

### 7. 治理、安全与审计

质询：哪些边界在后续推进中不能因效率理由放宽？

结论：

- V4 关闭锚点和原报告不覆盖、不重命名重开。
- 新口径结果与旧冻结 STOP 并列保存；即使新账务更好，也只用于决定是否值得注册新候选。
- 市场公开数据、研究重建账、Demo 成交账三类证据不互相冒充。
- 无账户凭据、账户变更、资金划转、采购、Demo 或 live 的隐式授权。
- 没有新事件或新输入时，不以重复运行、轮询次数、代码量或等待天数报告进展。

## 六、后续推进节奏

节奏按结果门禁，不按“持续运行了多少天”验收。市场事件时间用于计算与样本边界，阶段完成标准是明确的证据出口。

### 节拍 A：本次提交

交付：首期适配器、反例测试、CTest 注册、阶段报告、计划状态和本圆桌复盘进入同一可审计代码边界。

出口：本地提交成功，工作树中不混入其他项目的 publish 诊断；不自动 push、部署或访问账户。

### 节拍 B：下一次可部署窗口

在部署主机只读运行：

```sh
python3 tools/adapt_option_lifecycle_subaccount_v1.py \
  --root /opt/ai-trade/data/research/bybit_btc_option_lifecycle_v4 \
  --ledger-output /opt/ai-trade/data/research/option_lifecycle_accounting_c2/first.ledger-input.json \
  --report-output /opt/ai-trade/data/research/option_lifecycle_accounting_c2/first.adapter-report.json
```

必须留存：代码 release、raw manifest/checksum 身份、两个输出 SHA256、退出码和只读执行日志。

三个出口：

1. `SOURCE_EVIDENCE_GAP` 或输入无效：按 reason 停止，只修来源/完整性，不绕过检查。
2. 预期 `C2_FIRST_LIFECYCLE_ADAPTED_ACCOUNTING_INCOMPLETE`：确认真实路径已贯通，进入节拍 C。
3. 出现未预期的 ledger 通过、金额偏差或状态：视为需要调查，不能自动升级 C2。

### 节拍 C：首期缺项关闭

按 adapter report 中的真实首期持仓和事件，只处理以下有限集合：

1. 三个首期 funding 边界的结算资格；
2. 历史适用费用版本；
3. 普通 Cross margin 和订单占用的公式、参数与独立样例；
4. 首期连续 NAV/保守退出价值。

每取得一个来源，先做 checksum、语义、时间和单位反例，再接入 ledger。若现有归档不够，输出最小数据需求单；涉及付费或账户只读权限时停在批准点，不用更广的未经授权动作替代。

### 节拍 D：C2 独立对账裁决

同一首期至少由适配器账和独立手算/实现复算，核对：

```text
期末权益 - 期初权益 - 外部资金流
= option cashflow + hedge cashflow + funding + fees + financing + mark/settlement PnL
```

同时检查持有期 margin、订单占用、未知风险和保守退出状态。出口只能是：

- `C2_ACCOUNTING_QUALIFIED`：只表示一期集成与口径合格，不表示盈利；
- `C2_EVIDENCE_INSUFFICIENT`：列缺项、来源、最小恢复条件和是否需用户授权；
- `C2_RISK_OR_ACCOUNTING_REJECTED`：语义或资本约束不可接受，停止当前实现路径。

### 节拍 E：C3 六期完整归因

只有 C2 通过才把同一口径扩展到六期。并列报告旧冻结成本、新适用成本、真实 funding、gross、执行拖累、资本占用和尾部压力；不得覆盖 C1 STOP。目标是把失败分成账务偏差、成本不足、执行约束或资本/尾部不可行，而不是寻找能把旧结果改正的口径。

### 节拍 F：C4 单一新候选决策

只有 C3 支持一个实质机制时，才允许注册一个新候选。优先待证伪假设是“在预设风险预算下减少无效 hedge turnover，节约成本超过新增方向/跳跃/保证金损失”；它不是默认通过方案。

注册前必须固定：动作、资本、适用费用、风险预算、不交易/旧固定对照、development/selection/未见区间、最小有意义效应、检查点和停止规则。经济乐观上界仍不能覆盖成本或风险时，直接关闭本轮方向，不进入模型训练。

### 节拍 G：C5 新冻结前向

只有 C2–C4 均通过，才定义 F0 并开始等待新的完整生命周期。前向期只允许诊断数据、执行和迁移偏差；提前通过、停止、有效样本和多次查看规则在 F0 前冻结。达到统计与风险门后才提交 Demo 评审，仍不自动启用账户。

## 七、推进频率和汇报合同

- 每一轮只承诺一个可验证出口，通常为“代码 + 测试 + 真实/合成证据身份 + 决策报告”。
- 有新输入时立即推进，不为凑工作日等待；没有新输入时不重复运行相同分析冒充进度。
- 每次报告固定回答：完成哪一门、证据身份、金融/统计/部署/权限各自状态、剩余缺项、下一恢复条件。
- 外部依赖超过一个有效工作节拍仍未取得时，必须给出“继续投入能新增什么信息”的判断；不能自动扩范围。
- 首期输入可用后立即给出 adapter 裁决；C2 缺项取得后完成独立对账。需要付费、账户权限或产品决策时，列出具体需求并停在批准点。
- 旧计划的第 5/第 10 工作日已由结果门禁实施计划替代，本轮不恢复旧排期或资源时限。研究资格和路线去留由每次证据出口决定。

## 八、停止条件与用户批准点

立即停止当前推进分支的条件：

- raw checksum、生命周期身份或冻结金额无法对上；
- 需要使用交割后才可得行情、无 L1 容量或无法解释的时间倒置才能复算；
- funding、费用、margin 或 NAV 只能靠填零/无界假设才能“通过”；
- 普通 Cross 风险与用户要求的隔离资金边界不兼容；
- 新候选经济乐观上界仍无法覆盖成本或批准风险；
- 需要把旧六期再次当未见数据、修改关闭锚点或调低门槛才能晋级。

必须由用户另行批准：付费数据、账户/API 只读接入、创建或切换子账户、资金范围、风险限额、Demo、live、资金划转和真实发单。代码提交、离线检查和部署目录的只读研究重放不扩展这些权限。

## 九、最终决议

1. 本次代码具备提交条件；publish 诊断不属于本项目，保持清理状态。
2. 项目当前主阶段明确为 **C2 首期真实账务资格**，不是 C4 策略优化，更不是 C5 前向等待。
3. 下一项必须拿到的是部署 raw 上的真实 adapter report；它决定后续是修来源、补有限数据，还是进入首期独立对账。
4. V4 旧候选保持关闭；对冲成本诊断只保留为未来单一机制假设。
5. 在 C2、C3、C4 逐门通过前，不训练、不注册新候选、不启动前向、不申请 Demo/live。

这一路线保留项目已经形成的工程与治理资产，同时把下一单位投入集中到最能改变决策的证据上。最终结果允许是“通过、证据不足、风险拒绝或经济否定”，不以必须找到盈利策略为前提。
