# Bybit 永续新机制 G0 输入裁决

本轮按用户确认的[有界重启范围](../plans/2026-10-08-perpetual-g0-restart.md)完成
两个新机制的输入核查，结果为 **G0_NO_GO_INPUT_QUALIFICATION，选 0**。
没有进入 G1 至 G4，没有训练或收益计算。这是当前证据下的准入不足，不是两项
机制已被回测证明亏损，也不是全项目经济目标达成。预算尚未耗尽，因必要输入
和独立出口未绑定而提前停止，不以换参数、第三机制或漫长等待接续。

## 两个机制的实际发现

| 机制 | 已取得的证据 | 尚缺的决定性输入 |
| --- | --- | --- |
| S1 稳定币实际发行与购买力 | 公开供给序列 3,236 个连续日点；发行方定义；数据提供方固定版本适配器 | 实际发行事件、历史口径与可知时间的绑定，以及独立确认域 |
| S2 ETH 验证者退出与库存压力 | 官方共识代码、状态 API 规范、最新区块头 | 可用的历史队列／提款／合并输入及与再质押区分的卖压假设；独立确认域未准入 |

### S1 有供给历史不等于已有可交易的发行信号

[Tether 官方 FAQ](https://tether.to/en/faqs/)将库存授权和真正流通发行明确区分。
因此，看到铸币不能直接推断新增购买力。公开的
[DefiLlama 聚合接口](https://stablecoins.llama.fi/stablecoincharts/all)实读成功，
覆盖 2017-11-29 至 2026-10-08 UTC，共 3,236 个唯一连续日点，没有在本次检查
发现日间隔缺口。这里只核日期和字段，没有计算供给信号或任何资产收益。

固定版本[适配器源码](https://github.com/DefiLlama/peggedassets-server/blob/bef03c7d3c7ca432927e370f99d03f2550ec909e/src/adapters/peggedAssets/tether/index.ts)
分别处理 minted、unreleased 和桥接供给；部分分支忽略传入的历史时间，直接
调用当前透明度接口。**这不能证明原历史序列错误**，因为它也可能来自当时
保存的快照；但仅凭今天的代码重跑，不能认证原历史时点的信息集。

本次聚合响应没有逐事件分类、来源区块绑定或初发时刻。此缺口并不是“要求
API 必须有某个字段”：绑定过的历史快照、固定口径的链上重建都可以作为
替代证据，只是本轮尚未取得。不能把聚合差分直接改称实际发行意外并开始
优化。找到研究论文摘要也不等于获得可执行的事件时钟和成本后收益依据。

### S2 退出验证者不等于卖出 ETH

[Ethereum 官方 Electra 规范](https://github.com/ethereum/consensus-specs/blob/master/specs/electra/beacon-chain.md)
中的 consolidation 路径会设置源验证者退出时点，并把有效余额移交目标
验证者；只有超额等情形另有提款处理。因此，退出数量、提款数量和实际卖出
不是一个变量。这个源码事实说明需要分类，不证明退出信号没有预测价值。

[官方状态 API](https://github.com/ethereum/beacon-APIs/blob/master/apis/beacon/states/validators.yaml)
支持按状态身份查询验证者。本轮公开节点最新 finalized header 返回 HTTP 200；
固定 2024-01-01 附近 slot 8103598 的单验证者状态样例返回 HTTP 403、空正文。
内部原因 UNKNOWN，不能推断为历史被裁剪、供应商全无历史或全球无可用来源。
该样例不是完整历史队列；现有材料尚不能绑定预测时点的库存输入，也不能把
所有退出当抛售来凑事件量。未扩大为采购、归档节点搭建或长期前向采集。

## 为什么不继续到 G1

金融口径上，两项原始指标都存在清楚的非交易解释；不能把协议事实当利润。
计量口径上，必需输入未绑定，无法确定真实事件容量及独立确认分区，增加
训练模型不能修复这件事。工程口径上，接口可达、JSON 完整和实际信号合格
是不同结果，403 也不能通过改成空结果或补零放行。

现有 HAC 的 26 完整周最低长度保持；这不保证统计支持。没有把已见 BTC 历史
重新标成独立确认，也没有推断 ETH/SOL 的全部历史均已使用。两项确认域均未
准入，不能承诺等待一段时间就自动进入 G4。旧原安全撤回、候选资格和人工
Demo 禁开仓不改，V4 独立失败与本批经济裁决无因果归并。

## 访问限制与验收范围

共 22 次资料检索／读取操作、3 次匿名输入 GET，分别低于 40／6 的自限上限。
其中检索服务一次批量打开遭 401，涉及四个未返回正文的请求；论文 PDF 下载
40 秒后只收到 409,339／629,468 字节，未作为全文证据；ethereum.org 连接超时。
适配器猜测路径 404 后经仓库目录定位到真实固定版本，不把错误路径当数据
不存在。访问问题及有界替代路径见[具名记录](2026-10-08-g0-source-access-review.json)。

本轮未复验旧失败工作流、未重跑完整 CTest。9 项既有关闭约束回归通过、无
skip；8 个原 HAC 长度／符号边界通过，3,236 日网格、9 份本地来源及 41 份
保护原件身份一致。正式验证失败 0 次，本批 gate READY 仅表示这些资料检查
完成，**不表示 G0 放行**。完整机器结果见
[证据清单](2026-10-08-perpetual-g0-restart.evidence.json)。
本轮工程及交付保守计费上界 1 小时，占总 32 小时；不是把未用预算自动转为
下一批研究许可。35 份旧 gate 和选定的历史合同／配置等共 41 份原件受保护，
不声称扫描了全部历史原件。原始资料仅本地保留，公开交付为脱敏文档。

## 阶段结案

本次达到事前允许的不足出口，G1 至 G4 不启动，经济效果 NOT_EVALUATED。
重新接续需要改变这次判断的具体材料：S1 的历史发行分类／版本／时点绑定，
或 S2 的可用历史队列／提款／合并证据，加上可达独立确认出口；不是再运行
同一接口、另换模型或重新批准同样的四小时。本轮不追加第三机制，不创建
后台等待，不解除 Demo 禁开仓，也不宣称 G4 已通过。
