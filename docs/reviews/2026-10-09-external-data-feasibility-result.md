# 外部稳定币数据评估与采购前置条件

**本次评估完成，但没有形成可直接采购并推进 G4 的数据方案。** 外部产品能
减少自行恢复历史版本的工程工作，却不能自动补齐流通口径或独立确认资格。
当前建议不采购；保留 CryptoQuant 为一个待技术澄清的来源，不把它登记为
合格研究输入。Glassnode 的 PIT 能力值得保留，但不等于目标数据已可用。

## 三家供应商实际能解决什么

| 提供方 | 官方资料支持的能力 | 本项目仍缺什么 | 本次裁决 |
| --- | --- | --- | --- |
| CryptoQuant | supply 接口分列总量、铸造、销毁、流通、发行和赎回；流通量近似扣除发行方库存 | 目标币种与链的完整覆盖、历史库存标签版本、迁移／隔离处理及发布时间／修订记录；未取得样本 | 语义最贴近原问题，优先技术澄清，不采购 |
| Glassnode | PIT 数据不可回写，相关点可带 computed_at；官方说明 PIT 的起始覆盖限制 | 精确 USDT／USDC 指标是否扣库存并去跨链重复；目标指标实际 PIT 起点、发布边界及授权 | PIT 产品能力成立，目标输入资格未成立 |
| Coin Metrics | SplyCur 为链上可见存量；SplyFF 排除部分内部／长期持有；部分指标带人工审核状态 | 两者不能直接等同发行方全球流通负债；所读资料未证明目标序列可按历史版本取回 | 不能仅购买 SplyFF 就认定原缺件解决 |

CryptoQuant 的[稳定币网络数据定义](https://userguide.cryptoquant.com/api/stablecoin-network-data)
确实区分库存铸造与向客户发行；接口接受 token 和 day／block 窗口，公开示例
为 `usdt_eth`。这是有价值的语义证据，但不是所有链的全球流通量已核验。
该页响应说明没有绑定首次可用时刻与历史更正流水；其他交易所流量接口的
非 PIT 提示不能直接移植成“这个 supply 接口也已被证明非 PIT”。结论是待核，
不是供应商绝无能力。文档中的示例／空值亦不算实际 API 样本。

Glassnode [PIT 文档](https://docs.glassnode.com/data/point-in-time-metrics)明确：
2024 年 9 月开始记录相关 computed_at；它是进入系统的计算时刻，仍早于
API 发布，99 分位延迟约 9 分 42 秒，不是最大延迟保证。2025 年 7 月扩展到
全部指标；此前只覆盖列出的部分指标，新增指标不能回溯生成更早 PIT。
普通 supply/current 未列在此前清单中，精确资产起点仍需样本／元数据确认。
[供给定义](https://docs.glassnode.com/basic-api/endpoints/supply)中的 Total Minted
Supply 明确包含受限代币，不能拿它代替原合同的实际流通发行。

Coin Metrics [Current Supply](https://docs.coinmetrics.io/network-data/network-data-overview/supply/current-supply)
与 [Free Float Supply](https://docs.coinmetrics.io/network-data/network-data-overview/supply/free-float-supply)
各有用途，但不证明它们对目标稳定币满足发行库存、隔离及全链口径。
[字段说明](https://github.com/coinmetrics/docs-website/blob/master/asset-metrics/asset-metrics-overview.md)
中的 status-time 是适用指标的最后人工审核时间，不是普遍的首次发布时间；
revised 状态也不等于提供所有旧版数值。不能从文档中未找到某项能力，推断
供应商内部一定没有该能力。

## 费用与权限不应先于证据

[Glassnode 定价页](https://studio.glassnode.com/pricing)把 PIT 放在 Professional
范围，具体访问层级、API 和导出额度仍须配置确认；表格的 API Light 与 FAQ
对 Advanced API 的描述存在不一致。本轮不把低价入门档当完整历史 API 报价。
[CryptoQuant 文档](https://userguide.cryptoquant.com/api/stablecoin-network-data)要求
订阅后的访问令牌，定价页本次仅返回客户端页面框架，未核到可用总报价。
[Coin Metrics 入门说明](https://docs.coinmetrics.io/getting-started)要求多数数据用
API key，并按授权查看覆盖。三家的适用总费用均未核实，不填零或估造采购价。

没有使用现有账户、查找密钥、申请试用、发送询问或购买。公开网页读取不是
数据许可，订阅资格也不替代样本验收。原始供应商文档仅保留本地。

## 付费不能恢复已消费行情的独立性

这是与输入版本独立的第二个问题。现有两个统计实现仍在不足 26 个完整周
时返回 None；代码及历史失败没有修改。换供应商、特征或频率，不能让已见
BTC／ETH 市场时期变成未使用的独立确认域。

本次复核既有归档元数据：`market_alpha_history_report.json` 已记录 BTC 和
ETH 研究覆盖 2025-09-19 20:35 至 2026-07-19 20:30 UTC。其身份见
[旧输入审计](2026-10-09-eth-queue-input-admission-result.md)，不是重新下载行情。
对 **2025 年 7 月才新增的目标 PIT 路线**，即使乐观假定从 7 月 1 日完整可用，
只排除这一已见覆盖域、忽略其他已知访问，截至 2026-10-09 00:00 UTC：

| 乐观剩余区间 UTC | 完整日上界 | 完整七日块上界 |
| --- | ---: | ---: |
| 2025-07-01 至 2025-09-19 20:35 | 80 | 11 |
| 2026-07-19 20:30 后至 2026-10-09 | 81 | 11 |

这些只是未排除区间的长度上界，不是未消费认证；不能拼接为一条完整确认
路径。这项结果限定于上述 PIT 域，不声称所有供应商、所有历史均不可用。
更早版本仍需历史口径和使用记录；原 ETH 目标区间的独立性 UNKNOWN 及
S2 后续开发消费不能被采购消除。当前没有绑定可直接进入 G4 的历史出口。

若将来有值得确认的冻结模型，且明确接受前瞻成本，现口径至少需要 182 日。
例如仅假设 2026-10-12 00:00 UTC 开始完整冻结观察，26 周在 2027-04-12
00:00 UTC 才满；这不是已启动日程，也不保证事件容量、收益或统计通过。
现在没有合格模型，不建议先安排半年等待。改统计方法属于另一个事前设计
决定，不能为已见结果缩短门槛或追溯改绿。

## 下一份证据应一次回答的四个问题

如后续允许对外技术联系，优先给 CryptoQuant 一份完整询问，而非先买套餐
或逐次申请取数。以下内容已准备好，**尚未发送**：

1. USDT／USDC 的 token 与链覆盖、起止时刻、频率及缺失清单是什么？如何
   扣发行库存和隔离余额，处理链间迁移与桥接重复？请给出具名方法版本。
2. 历史库存地址标签、回补和修订如何保存？是否能返回某个决策时点真实
   可取得的版本及可靠可用时间边界，而非当前重算表？可信采集流水可接受，
   不要求每行另有第三方网页存证。
3. 能否先提供 2023-06-01、2024-06-01 固定控制日及其前一可用版本、覆盖
   元数据与版本说明？缺某控制日请明确说明，不选择有利日期替换。控制点
   只能核语义与时钟，不能认证全历史或盈利。
4. 上述精确数据范围的样本许可、内部回测／持续采集许可、导出方式、更新
   延迟约束、费用和最短承诺期是什么？无需提供价格收益或定制盈利回测。

先取得这组证据，并绑定独立确认出口，再决定是否值得付费。只有口头承诺、
当前 API 成功或部分示例，不启动采购／整段下载／模型开发。本批不自动授权
发送询问；用户也可直接提供已有供应商材料，不需要在聊天中粘贴凭据。
