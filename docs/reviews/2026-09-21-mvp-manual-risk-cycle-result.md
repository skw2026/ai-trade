## 1. 已固定并实现的人工规则

| 环节 | 生效规则 |
|---|---|
| 触发 | 原 8/12/20% 动作不变；12% 冷却、20% 熔断后保持锁存，无批准不恢复 |
| 首次人工恢复 | 全平、无任何待处理订单、通道健康、无强制只减仓；满足冷却观察 24h |
| 批准身份 | 一次性 approval ID、非空复盘引用、当前周期序号与当前已观察时间；过时、重复、错周期均拒绝 |
| 周期预算 | 人工明确名义上限（不得超过原 gross cap）及损失金额（不得超过新周期初始权益的 2%） |
| 分段 | 25% → 50% → 100%；每段至少 24h，升档也须新的人工批准且全平/无待单/健康，不自动升档 |
| 再次停止 | 净损失或距周期峰值的损失金额触及预算、DD 锁存线、7 日到期，任一触发即重新锁存；不能复用旧批准 |
| 旧账 | 不写账户现金、累计盈亏、费用/funding、高水位；保留全生命周期最大回撤和永久的 20% 触线事实 |
| 在途风险 | 全 symbol 执行串行保守放行：存在待处理订单时不新增敞口，不提前使用未成交减仓“释放”的资本；锁存后下一个开盘前撤销入场单 |
| 持久化 | 批准和观察先追加 journal 并 fsync，成功后才提交内存状态；写入失败停止，不能继续放行 |
| 重启 | 已存在 journal 的同目录启动拒绝，原文件不覆盖；不把 replay 跳过旧 WAL 恢复当成清除锁存的理由 |

24h、分段、2% 和 7 日是合成测试前固定的保守离线规则，见[实现合同](../plans/2026-09-21-mvp-manual-risk-cycle.md)，没有按收益结果调参。**预算是风险触发线，不保证跳空时实际损失被精确封顶。** 模拟时间推进不要求用户真的等待一天或两周。

新周期的 control DD 相对获批时权益计算；旧账户 DD 不重置。例如合成旧损失 21% 后人工恢复，当前周期 DD 可为 0，但账户 DD 仍为 21%，生命周期触线事实仍为 true。即使后续盈利超过旧峰值，历史最大回撤和失败事实也保留。

## 2. 代码入口与验收覆盖

- `src/risk/manual_risk_cycle.{h,cpp}`：独立的锁存/批准/预算/分段/审计层。
- `TradeSystem::OpenMvpRiskJournal`、`ApproveMvpRiskCycle`：仅 `closed_bar_mvp` 的受控离线 API，审批落盘后才重建周期风险滞回；强制只减仓不被清除，旧 alpha 缓存丢弃，等待下一闭合 bar。
- `AccountState` 只增加只读 peak accessor，账务实现不改；风险引擎只增加由 orchestrator 受控调用的私有周期入口，旧风险解析实现不改。
- `BotApplication` 在连接本地 replay 前建立独占风险 journal；异常时以非零退出停止，不自动重试恢复；原同事件成交辅助入口 `OnPrice` 在新模式被拒绝。
- 新增 `manual_risk_cycle_test`；既有 `mvp_contract_test` 增加完整应用日志持久化与同目录重启拒绝断言。

关键合成证据：

1. 13%/21% 损失全平后，各推进 2016 个 5m 时刻，无人工批准仍锁存。
2. 24h 边界、25/50/100% 限额、逐段手动批准、7 日精确到期、重复/过时/错周期/缺复盘/超预算/持仓/待单/不健康/强制只减仓拒绝均通过。
3. 不仅检查状态名：使用冻结 MVP 参数预热 289 根合成 bar，批准后实际产生非零开仓决策，原信号超过批准限额而最终目标不超过 25% 上限；有其他在途订单时不得再开新风险。
4. 费用与 funding 纳入损失预算；接近预算时不提前触发，等于预算时重新锁存；盈利后的峰值回落也受预算约束，大跳空仍触发周期 Fuse。
5. 审计写入失败不能释放状态，即使随后 writer 恢复也不自动放行；时间倒退停止。同目录进程重启拒绝且旧文件大小不变。

7. 上一阶段的 closed-bar 一致性、未来价格不泄漏、下一开盘成交、funding 顺序和 EOF 平仓回归仍通过。

金额、损失和行情均为人工 fixture，**不是 Bybit Demo 账户数据或真实收益**。文件、二进制和门禁身份见[证据清单](2026-09-21-mvp-manual-risk-cycle.evidence.json)。上一阶段 99 项结果及其失败复盘不改写，作为当时快照保留；当前变更用新的身份清单记录。
