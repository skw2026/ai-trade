## 三方质询与合并结论

| 视角 | 发现的根本缺口 | 处理决定 |
| --- | --- | --- |
| 部署工程 | 单测没有同时覆盖实际 umask、写入 UID、回放 UID 和封存就绪，造成三次现场失败 | 统一检查整个部署生命周期，不继续按症状补权限；回放前绑定原采集源码、镜像、mount、属主及原件清单 |
| 流程与审计 | 原失败 run 固定旧 SHA；重跑不能使用修正代码。本批已明确最终停止 | 不做第四次旧 run，不重置 gate。正式纠正必须明确越过本次停止出口的范围，并绑定新控制器 SHA/run，原失败和 HALTED 保留 |
| 金融研究 | 六频道提供盘口和成交流，但不是完整策略机制、执行成本或永续风险账 | 不把数据量、回放或零交易当经济进展。长采之前先明确一个研究问题及其必需字段、连续窗口和成本处理 |

部署方对研究方质询的答复：94 个独立连接段不能无条件拼成连续路径。
每段约 15 分钟，段间缺口需要显式量化；一小时完整回看、跨段持仓和成熟
标签都不能直接假定可用。首段 65 秒只能验证短段工程流程，不能验证五分钟
持有标签。整批 hash 一致也不能解决这些经济输入限制。

研究方对工程方质询的答复：现在先做同链回放和恢复仍然有价值，但不能
由此默认启动一个旧失败族。净效用回归、方向与期限排序、NO_ORDER 已经
做过，改成“在线学习”名称不是新的收益机制。冻结学习规则不等于权重
永远不变；后续可评估预先固定的自适应算法，不能看到收益后改学习方法。

流程方对工程接续的答复：普通修复、诊断和提交无需逐步授权；这次确实
存在已明确写入的“三次后 HALTED”终止边界，不能把它称为普通 retry。
已经向用户提出一次限定纠正验收例外，未答复前只进行只读取证和限定修复。
实现细节不再拆成审批项，也不改造通用 gate 或重开策略预算。

## 先前置裁决 再决定是否需要继续采集

纠正工程的固定对象应是原批次、原首段和已完成的 94 段清单，不重采以换
样本。分别报告身份绑定、整批封存完整性、首段断网回放、私有异机恢复，
不把单项通过外推到全部。跨机回放应使用相同固定镜像及平台，避免把 Python
或 libm 浮点差异在失败后临时改成宽松容差。

研究登记前必须先写清特征可知时间、决策、执行延迟、成熟标签、扣费账和
更新顺序；最长回看加持有期必须有可用连续输入，且预先规定断流及持仓处置。
当前实现只检查各频道曾出现及总体间隙，尚不能证明每个币种报价始终新鲜；
没有成交也不必然是频道故障，二者要区分。

永续净收益如涉及资金费结算或标记价风险，需要相应输入及时间语义。Bybit
公开 ticker 提供 markPrice、fundingRate、nextFundingTime，instrument
接口提供价格／数量规格，但这些字段目前不在本批六频道采集范围内，且
预告费率不能直接充当实际结算账。
参见[公开 ticker 文档](https://bybit-exchange.github.io/docs/v5/websocket/public/ticker)
和[合约规格文档](https://bybit-exchange.github.io/docs/v5/market/instrument)。
index 仅在研究或风险模型实际依赖时要求，不为增加门槛而额外强制。

本轮尚无可登记的新算法或经济结论。不能默认再采一天、等数周或承诺某个
夏普率；G4 独立资格、旧策略关闭与 Demo 禁开仓均不因这次复盘改变。
