表中发出时间来自执行工具在 curl 前输出的 `date -u`，不是从响应头 Date
倒推。复查响应头的 Date 也为08:16:05；原始工具执行记录与本地响应分开保存。

首次失败立即停止循环，没有读取后续边界。首次未保存响应头，是本次取证
设计的缺陷。经[方法及工程复核](2026-10-12-aave-annual-rate-limit-review.json)，
在原40次/08:57 UTC内追加一次实际重复读取：不是另一个新请求，不是原
HALTED正式复验，也不是把冻结计划的“不重试”偷偷改写。三分钟以上不访问
数据主机之后，用同请求身份与参数复查并保存完整响应头；再次失败后停止。

第二次响应头为：

```text
x-ratelimit-limit: 10
x-ratelimit-remaining: 0
x-ratelimit-reset: 2634288
```

已确认：服务报告本请求受限，当前响应所示额度为10、剩余0。未确认：具体
桶的作用域、时间窗口、reset字段单位/含义及何时恢复。没有 Retry-After。
不把 reset 猜成秒、毫秒或Unix时间；也不把一次等待说成修复成功。此前
已成功7个日志请求、3个月首请求，与10次相符，但这不是服务器部署配置证明。

## 对推进节奏的决定

[官方额度说明](https://docs.blockscout.com/rate-limits)提供免费 PRO API key：
5 RPS、每日100K credits；默认20 credits/调用约5,000次/日，部分端点更贵。
这是带key方案的公开规则，不能倒套匿名 `eth.blockscout.com` 的限额。

相比继续探测匿名入口，接入已有授权key或由用户创建免费key，是更具体的
下一步。无需另建交易项目、钱包、私钥或资金，也不涉及采购；但新外部
账户注册/服务授权不由代理擅自完成，不把服务网页说明当本项目已有权限。
key只能经本机私有配置接入，不贴聊天、不入git。本轮没有访问账户或注册。

有授权输入后，先按具名接续核地址/权限/额度，再补原固定2024域的缺件；
保留旧失败和零事件控制结果，不换年、不看价格、不直接启动经济实验。
仍需全量日志、匹配回执、DEX净流归因及完整取数成本，之后才能决定是否
值得做唯一开发筛查。当前不能估计Sharpe、回撤、盈利或自学习增益。
