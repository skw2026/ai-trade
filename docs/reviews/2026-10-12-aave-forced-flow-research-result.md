# Aave 新机制立项与输入核验结果

本轮已选定一个与旧合同有实质区别的研究对象：**Aave V3 WETH 清算伴随
同交易 DEX 净出售后，ETH 永续是否还有费用后的下行传导。** 三方审查支持
它进入输入核验，不是已支持盈利或自学习。当前结果为
`MECHANISM_IDENTIFIED_INPUT_ACCESS_BLOCKED`：首个真实数据入口拒绝访问，
输入未准入，未读取行情或计算收益；G4 未达成，Demo 禁开仓保持。

## 这次没有重复哪些旧路线

查重发现 BTC 周频趋势已经按 7 日回看、7 日决策完成过风险否定；Bybit SOL
强平信息集也已做过秒级信息和方向／期限实验。因此两者不以「降低频率」
或「改成 ETH」重新命名立项。原 maker、carry、期权、供给及其他关闭不改。

对当前已跟踪文件及相关目录的定向检索，未发现 Aave／Compound／WETH／
LiquidationCall 的旧研究合同。此检查没有覆盖已删除 Git 历史或仓库外资料，
不声称所有地方从未研究。新增对象的区别在于链上抵押信用合同与可核验的
现货交换路径，仍与旧强平同属杠杆去化，不能称完全独立或外生因果。

## 收益假设与强反证

[BIS 官方研究摘要](https://www.bis.org/publications/working-paper-1062-systemic-fragility-decentralised-markets)
观察到清算者出售抵押品及价格影响向链下市场传播，支持提出残余传导假设。
[加拿大央行 Aave V3 研究摘要](https://www.bankofcanada.ca/2026/04/staff-analytical-paper-2026-13/)
则指出对更广市场影响有限。两者不能替代本项目的成本后证据，也不能据此
挑选历史暴跌日。只读取了这些官方页面的摘要／介绍，未把全文当成已复现。

清算折价属于清算者，不是我们的收益。`LiquidationCall` 只是抵押转移；
同交易出现 DEX swap 也不自动证明卖的正是本次抵押品。需核池资产、净交换、
闪电贷、旧库存、回购与多跳，歧义保留 UNKNOWN。已经完成的卖单不能当成
未来待售库存；拟检验的是后续去杠杆簇的预测增量，并需普通跌势对照。

## 真实输入核验

按[收益前冻结的范围](../plans/2026-10-12-aave-forced-flow-research.md)，使用
[PublicNode 官方公布的匿名 Ethereum 入口](https://ethereum.publicnode.com/)，
先请求只读 `eth_chainId`，未接触任何钱包、账户密钥或交易方法。

| 检查 | 实际结果 | 可以得出的结论 |
| --- | --- | --- |
| 首次原命令 | `SSLCertVerificationError`，未收到 HTTP 响应 | 本地 Python 缺默认 CA，尚未取得链信息 |
| 系统 curl HEAD 对照 | TLS 验证通过，HTTP 405 | 该主机可完成系统信任链校验，不证明 RPC 可用 |
| Python 系统 CA HEAD 对照 | 主机名／证书校验保持，HTTP 403 | 缺省 CA 问题可被正确修复，服务仍可能拒绝请求 |
| 具名复盘后唯一原命令复验 | HTTP 403，完整 17 字节正文 `error code: 1010` | 入口拒绝已确认，内部拒绝原因 UNKNOWN |

原失败和复验原文分别保留在私有取证目录，不覆盖请求占位。没有第三次
RPC、更换请求头绕过拒绝、关闭 TLS 校验或把 HTTP 错误记为空事件。
两次 RPC 尝试均没有取得 chain id；区块、清算日志、receipt、DEX 净流、
完整事件容量和任何收益仍 **NOT_EVALUATED**。

[TLS 根因与唯一复验记录](2026-10-12-aave-input-tls-review.json)及
[访问失败停止与路线复核](2026-10-12-aave-input-access-stop.json)保留两个失败。
这不是对所有免费 Ethereum 数据入口的穷尽，也不是对该机制的经济否定。

## 三方复盘后的去留

- 新颖性审查：支持它作为本轮唯一新输入对象，不重开旧交易所强平源。
- 金融审查：有可检验机制，也有传播很弱的反证；先输入、成本和独立事件
  容量，不要求先证明盈利，但也不把有被迫卖家等同于我们可盈利。
- 方法审查：区块时间不等于历史接收时间；清算内生于跌价、同波次不可
  拆成独立样本。固定规则即使将来开发通过，也不能证明学习增益或 G4。

当前阶段停在**具体入口的访问失败**，不是市场观察。继续需要实际可读的
Ethereum 历史区块／清算日志／交易回执来源，先完成有界纠正输入验收；
仅取得新 URL 或 API key 不等于输入通过。后续仍按原机制检查交易内净流
与事件容量，再冻结经济合同，不靠增加论文、通用 K 线或重复同一请求推进。

用户说明当前只有仍在落地中的 ai-trade 项目，未提供现成 RPC 服务信息。
RPC 在此仅指读取公开区块数据的 API，不需要另建项目、钱包或转入资金；
不能据此假定已有入口，也不把搭建节点或采购服务转交用户作为默认前置。
数据可得性仍是研究方应先验证的依赖，后续应先解决有界输入访问与完整性，
再投入策略实现。未索取私钥、助记词或要求公开 API 密钥，没有配置后台
采集或默认等待期，没有新增候选研究或费用。

## 工程与投入边界

合成检查在真实网络操作前通过 **13 项**，覆盖链身份、错误响应、区块时间、
事件 ABI、重复日志、请求 hash、失败前驱和一次性网络占位。固定事件 topic
用 OpenSSL 3.6.3 的 Ethereum Keccak 独立计算，并用空输入已知向量验证，
未用 NIST SHA3 替代。输入读取成功始终不等于完整历史或卖压可识别。

TLS 补丁保持 `CERT_REQUIRED` 和 hostname 检查，原命令复验确实推进到 HTTP
层但仍失败；没有将补丁后的全套测试或全项目 CTest 冒称通过。新阶段 gate
以 HALTED 保留实际失败，不改旧 gate。201 历史原件及旧报价结果未改。

本轮共占 24 次资料操作额度，其中经济审阅者最后 3 次是工具级 HTTP 401
失败；另有 2 次 RPC 尝试和 2 次 HEAD 诊断。0 行情／收益／训练／账户／
下单／交易部署，未启动后续 60 请求额度。本轮按访问不足出口停止，四小时
是上限，不填满工时或借用旧 32 小时未知余额。

工具与必要脱敏记录按仓库规范 main `[skip ci]` 交付；私有原响应不上传。
本次交付是新机制及真实阻断定位，不是全项目完成或盈利证据。
