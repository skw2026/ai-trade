## 两次实际失败和一次启动错误

1. 全量启动最初给验证工具设置了不支持的 7,200 秒外层超时，命令在子进程
   执行前被拒绝，未创建正式 run 或发出新请求。核对工具 3,600 秒上限后
   修正启动参数，未修改采集或验收代码。见[启动复盘](2026-10-13-aave-economic-launcher-preflight.json)。
2. 第 541 次请求：HTTP 200／curl 0，正文 `10016 / Get kline failed`，立即
   BLOCKED。官方 REST 错误表将其归为服务端错误，具体内部原因仍未知。
   经[具名复盘](2026-10-13-aave-market-server-error.json)，超过 60 秒后仅一次
   原 argv／cwd 复验，保留 540 页缓存；原失败页随后按原条件通过。
3. 复验至总第 788 次请求：HTTP 200／curl 0，正文 `10006` 明确报告 API
   限流。没有继续第三次尝试；本阶段 gate 已 **HALTED**，两次失败均保留。
   [停止与路线复盘](2026-10-13-aave-market-stop.json)记录全部证据和边界。

[官方错误码](https://bybit-exchange.github.io/docs/v5/error)区分服务端错误和限流；
[官方限额说明](https://bybit-exchange.github.io/docs/v5/rate-limit)给出适用的
限额／剩余量／重置时刻响应头。本次冻结采集器未保存这些响应头，所以
**具体限流桶、有效额度、出口是否共享以及恢复时刻均未知**。每秒一次只是
本地节奏，不是供应商保证。不能把 HTTP 403 的等待建议套成此次 10006 的
恢复时间，也不据此宣布必须等待十分钟、一天或数周。

## 多视角阶段复盘

以下是基于同一证据的不同审查视角，不冒称外部专家会议或独立专家意见。

| 视角 | 当前结论 | 不应采取的动作 |
| --- | --- | --- |
| 金融机制 | 净卖压传导仍未获得本次经济证据，不能判断可盈利或已证伪 | 翻方向、改变持有期或成本来寻求正收益 |
| 计量和数据 | 全域输入未齐；事后改用成功前缀会改变冻结样本 | 将前 210,000 根当完整年度，删除缺页或 UNKNOWN |
| 数学和账务 | 合成现金、风险区间及 HAC 包络成立，真实四账未运行 | 把数学测试通过当统计支持或 G4 |
| 工程交付 | 长链请求缺少可核限额信息，一次全局续取不足以保证交付 | 继续手动重试、猜重置时间、换 IP 或账户绕限 |

我在本轮把每秒一次作为交付节奏，却没有先保留限额恢复信息，这是取数
设计需要补齐的工程缺口。修这个交付边界应与经济模型分开，不能继续要求
用户为每个网络错误逐次放行，也不能事后把旧 FAIL 改成可忽略的成功。
