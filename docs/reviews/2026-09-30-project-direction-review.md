# 项目级深度复盘：没有策略交付，研究方法与推进方式需要纠偏

日期：2026-09-30。代码基线`dc6a963`。用户连续要求全面、深入分析，并指出
“目前可以说毫无进展”。本轮没有新回测、训练、市场数据或账户访问。
只读核查范围见[复盘边界](../plans/2026-09-30-project-direction-review.md)，
关键复算见[机器证据](2026-09-30-project-direction-review.evidence.json)。
以下为同一审查者从产品、研究、统计、工程和风险视角的交叉检查，不冒充
外部专家认证或多名独立审查者结论。

## 1. 先给项目级裁决

**以用户要的“能够学习、具有可验证成本后优势、能进入Demo验证的策略”衡量，
目前没有完成任何可交付的策略成果。** 有工程资产，但不应再用124项测试、
提交数量、报告数量或运转天数证明核心目标取得了进展。

三个结论必须分开：

| 问题 | 当前回答 |
| --- | --- |
| 执行账、审计、有限调权和安全拒绝是否有工程证据？ | 有。不能倒退成“什么代码都没用”。 |
| 是否已有合格自学习策略或独立净增益？ | 没有；最新0更新、0配对增益、确认0次。 |
| 是否已证明“自学习交易这个方向不可能”？ | 没有；现有实验不足以支持如此大的结论。 |

**应停止的是当前这种推进方式，不是宣布所有学习方法无效。**
“失败→换机制/补资料/修工具→技术通过→再开下一批”的循环，至今没有稳定
回答一个可交付策略的经济问题。当前固定实验的NO_GO与关闭锁存仍然有效；
本报告不修改旧数据、策略、收益、门槛或风险规则。

## 2. 目标到底有没有偏移

原始PRD `aa5a6da:docs/需求描述.md`明确：BTC/ETH/SOL永续，5分钟主信号、
15分钟/1小时辅助，秒级风险执行；趋势与受控Bandit调权；不承诺稳定收益，
也明确不做MVP高频做市/亚秒抢单。当前[需求](../需求描述.md)后来增加了离线
Miner/Integrator、7/30/90天学习参考和训练—确认—运行的阶段边界。

因此：

- 原目标本来就有风险限制和不盈利出口，不能把不收口归因于用户要求保证赚钱。
- 策略调权本身是一种合法学习方式，不能反过来说“不用大模型就不叫AI”。
- 但从分钟永续转向亚秒maker、跨场carry、期权、事件与外部历史版本，每一次
  都产生新的数据和金融语义问题。这些阶段有各自同意，不等于每次越权；
  问题是累计路线没有对同一产品结果收敛，串行批准代替了项目级去留判断。
- 最近两轮又缩回三桶权重，却没有清楚说这是一个很窄的控制器实验，不是
  对完整因子发现、参数学习、预测建模或整体自学习可行性的检验。

责任不在于用户说了太多次“继续”。我应该在每次继续前判断动作是否改变
决定性证据，而不是把连续工作理解为总能找到下一项可实现的工程任务。

## 3. 新核实的事实：两轮没有带来独立的经济覆盖

### 3.1 最近两轮实际用了同一个很短的前缀

逐行比较9月29日和9月30日已封存轨迹：共同768根bar中含480根开发bar；
六组账本的`cash/qty/fees/slippage/funding_paid/turnover/fills`**逐值完全相同**。
旧轮多消费一根bar，两轮退出时点不同，最终净收益不同不能解释成学习改善。

2025全年105120根开发bar，本轮实际消费480根，即**0.4566%**，完整周为0。
两轮不是两份独立市场验证，不能累计称为两次支持或反对自学习的独立证据。
新净收益记账与样本桶修复有工程价值，但没有给出新的有效策略动作路径。

### 3.2 “学习器”实际可改变的东西很少

本轮只允许三桶的趋势/防御配比，底层EMA12/26、rank20、Regime、信号参数
都固定，没有拟合新的预测模型。15个名义候选槽位在初始0.5权重下只有13个
不同全向量；每窗只选一个桶，受±0.05步长限制，当期真正可选为0.45/0.50/0.55。

这能回答“这一小组现成配比在这一前缀是否足以通过更新规则”，不能回答
“价格信息能否学习”“学会选择交易时机能否盈利”或“全部AI方法是否值得做”。
所有被评估候选在两窗内净亏是真实结果；候选槽位数不是独立假设或独立样本数。

### 3.3 停止原因不是8%回撤触线

本轮基础参考最大回撤1.57047%，低于8%；先触发的是**连续两个20小时负窗口**。
代码既停止模拟组合，也停止整个研究runner继续读取数据和学习。
安全停止与参考风险停止不能混称，更不能说必须放宽8%才能获得更多研究证据。

## 4. 最重要的方法问题：把几个不同层级合在了一起

### 4.1 开发学习、策略应用和上线资格不是同一件事

当前`LearningWindow.finish()`要求训练、留出、基础、压力四项净收益全正，才
可能应用一次权重更新；候选比较会利用负收益信息，但不会将“仍亏、已有
改善”的候选应用到后续影子路径。这个选择对受保护的在线应用有理由，也
符合已批准合同，不是一个可以私自删除的bug。

问题在于：用户要求“开发内允许有界学习，再验证值不值得继续”，最近的
实验却主要沿用了在线安全应用规则。**模型内部学习/优化也能从负样本学习；
允许离线优化一个尚不合格的模型，不等于允许它交易或取得资格。** 当前没有
完成一个分离后的有界开发训练、冻结选择、独立经济确认流程。

纠偏也不能变成相反错误：不能强迫应用亏损候选来凑更新次数，更不能把“少亏”
当作经济成功。最终绝对净收益、配对收益、成本压力、风险和独立证据仍须检验。

### 4.2 交易停止不必在所有研究设计中等于数据研究停止

旧两窗撤回必须保留。一个可能的新研究设计应当允许：模拟策略触线后永久
关闭该条交易路径，保留亏损与失败；离线研究在事前限定训练域内继续处理
样本。不能重置账户、删除坏区间、从触线后重新入场，不能把这些行为包装成
“继续训练”。是否采用该新语义，是实质设计决定，本轮没有实施。

本次40小时早停对“原策略按此保护规则应否运行”有明确答案；对“用固定
全年开发域研究后是否能形成有界改进”没有足够覆盖。相反，把短前缀不足
当作可以无限续样本的理由也错误：研究必须有总预算与一次明确终点。

### 4.3 统计门槛与样本单位没有形成清晰的层次

每桶120条、留出72bar的t门槛不能解释为120个独立交易。串行5分钟收益具有
依赖，滚动窗口和相同原始历史也不独立。最终26完整周HAC门槛本轮一次都未
进入，因此没有最终统计通过，也没有最终统计否定。既有代码没有伪称通过，
但项目计划未在开始前说明：早停后能回答什么，不能回答什么。

## 5. 新定位的执行结构问题：时钟和目标变化

`RegimeConfig.ewma_alpha=0.2`在`IntervalAwareAlpha`中明确以5秒为基准；
研究driver每根输入为300秒。有效系数：

`alpha_eff = 1 - (1 - 0.2)^(300 / 5) = 0.9999984675`

也就是旧状态仅保留约0.00015325%，等效物理半衰期约15.53秒。同时
`switch_confirm_ticks=0`，每根即可转换。公式本身没有算错；这是研究合同把
该物理记忆长度与5分钟采样、不同周期策略组合在了一起，不能未经批准改成
另一个参数然后声称修了普遍程序缺陷。

已消费479个有效决策信号中，桶切换239次；240段连续桶状态中143段只有一根。
成交原因进一步拆分为：

| 实际成交变化类型 | 次数 | 已付手续费与滑点 |
| --- | ---: | ---: |
| 首次建仓 | 1 | 0.791588 |
| 原始方向与桶同时变 | 77 | 45.600936 |
| 原始方向不变，仅桶缩放变 | 98 | 42.461500 |
| 仅原始方向变 | 75 | 58.245006 |
| 终止平仓 | 1 | 0.752882 |

98次桶缩放交易已逐项验证：趋势金额不变，防御方向不变，除以桶缩放系数后的
防御金额相同。不同桶的防御缩放0.35/1.00/0.55会直接改变目标仓位。

这不是泛泛的“可能换手高”，而是可以定位到参数语义和动作链的具体设计。
但它**不证明放慢Regime或删除这98单就能盈利**：其他152次方向相关变化仍在，
少交易会改变持仓、毛收益和风险；42.46不是可直接兑现的节省。不得保持旧毛
收益不动后减掉费用，伪造新策略回测。本轮没有计算任何新参数的收益。

## 7. 为何多次复盘没有转成收敛

9月5日[路线图](../plans/2026-09-05-evidence-first-delivery-roadmap.md)已经要求
有限总预算、经济前置、阶段退出；9月20日[项目复盘](2026-09-20-project-comprehensive-roundtable.md)
已指出“把不确定的研究当成工程依赖补齐就必然结束”的错误。
因此本次不能把同一句原则再写一次当作改进。实际问题是：

1. **局部完成替代了项目完成。** 很多工作能以测试/合同/hash完成，但合格
   策略数量仍0；用户得到“已完成”的密集反馈，核心结果却没有移动。
2. **小批次上限没有约束累计投入。** 每轮结束后又提出下一轮，局部有界并不
   等于整个项目有界。不能把后续普通“继续”当作无限研究预算。
3. **没有稳定的研究问题。** 测量修复、市场假设、资格治理和运行可靠性
   经常接成一条链；证明一个问题不等于接近另一个问题的通过。
4. **前置方法审查仍不足。** 最近才修样本桶遮蔽、才把代理目标换成执行账，
   又在本次发现时间尺度及早停解释边界；这些应先于声称“验证学习方向”。
5. **工程推进替代了去留决定。** 缺确认数据时补工具、无候选时补治理，
   容易持续产生工作而不产生新经济信息。旧发布BLOCKED也不是当前没有alpha
   的原因；修好push不会让失败策略有效。
6. **状态入口落后于事实。** 本轮开始时README仍首先展示9月23日工程交付，
   而经济状态已多次变化；本轮将入口更新为当前“无合格策略、方向复盘”状态。

上述过程责任由执行者承担。用户要求及时停下分析是正确约束，不能用它来
解释为什么反复没有结果；问题是我没有持续把局部合同与全局问题对齐。

## 8. 纠偏方案：只保留一个实质决定，不再自动接下一机制

**推荐先纠正研究语义，不立即换新策略、不继续补通用框架。** 这不意味着
正确方法必然盈利，而是先确保下一次失败或成功真的回答用户的问题。

唯一需要决定的改变是：允许单独的、总预算固定的离线开发优化流程，能够
从负样本改进；与候选应用、模拟交易安全退出、最终确认和账户权限严格分离。
旧实验不恢复、不翻案；新的范围要明示，不借“修bug”绕过原关闭。

若决定继续，只建议**最后一个16有效工程小时的方法纠偏批次**（方案，尚未
启动；不是收益或Demo交付承诺）：

| 阶段 | 共享预算 | 固定交付与出口 |
| --- | --- | --- |
| 研究合同纠正 | 前2小时 | 明确唯一学习对象/允许字段、时钟单位、训练/开发评估分区、总候选数、净收益目标和预算；不能与已关闭族改名重复。容量或方法不可达即停。 |
| 最小改造和有界开发 | 累计至10小时 | 复用现有账本和研究代码，不再建一套框架；只允许一个自适应方法和固定基线，最多一次市场尝试。内部优化可使用负样本，不等于策略获准应用。 |
| 冻结结果与独立核验 | 累计至14小时 | 对事前固定开发评估域报告所有失败与停止，不挑日期、不清除损失；绝对净值、双倍成本、配对增益、方向暴露、周块不确定性一并交付。 |
| 项目去留 | 最迟16小时 | 无经济支持则停止本次策略研发，不自动接“换模型/换币种/找数据”下一轮；有开发支持也只形成待确认候选。 |

硬边界：

- 模拟交易触线后该路径保持终止/空仓，不复活；账户安全、8%参考风险及
  实际交易8/12/20动作不因离线优化改变。不能删除坏窗口让全周期好看。
- 训练与开发评估的划分不是新“未见确认”。已见2025历史仍只有开发身份。
  目前确认区间null，故即使新开发成功，也不能承诺16小时交付可用Demo策略。
- 最终确认必须先有来源与使用记录明确、从未用于选择的区间，再固定样本
  与时间要求；不能默认等两周，也不能把日期后移就称为独立证据。
- 不强制更新，不把全空仓零收益算盈利策略，不以只有相对少亏替代绝对经济性。
- 不购买数据、不访问账户、不部署、不解除旧发布BLOCKED；内部实现不逐步索权。

如果不接受这个研究语义改变，合理选择是按“工程资产已保留、策略研发没有
合格成果”停止，而不是继续旧命令。**当前不能负责任地保证哪条策略能盈利；
可以保证下一步的研究问题、成本、失败出口和结论范围必须事前讲清。**
