## 新增了什么证据

固定在 Pectra 前的历史文件版本，取得 702 个不同 SHA 的完整分页元数据：
693 个有绑定同一 SHA 的历史成功部署记录，另 9 个缺部署成功状态的版本均在
公开事件档案找到对应 SHA 的评论时间。部署控制来自
[GitHub 历史部署](https://api.github.com/repos/etheralpha/validatorqueue-com/deployments?sha=639fa417c92e821f6969073c5b165eba85064811)。
这里记录的是“有历史发布／部署时间依据”，不把 Git 提交日期单独当可知时间，
也不把当前部署可访问性或第一条已留存记录冒称首次公开时间。

另下载 [GH Archive](https://www.gharchive.org/) 的 2024-01-01 00 时原始归档：
153,619 个事件中，目标仓库的公开 PushEvent `34495570853` 在
`00:30:18 UTC` 明确绑定 SHA `639fa417…`；历史成功部署在 `00:30:24 UTC`。
这是一条独立原始控制，不能外推成全部 702 个版本均已逐条核对原始推送正文。
其余元数据使用公开只读查询和 GitHub API；数据包留在本地，不上传其他事件正文。

已读取 9 个固定版本正文，末日依次为 2023-06-04、09-01、12-01、
2024-01-01、04-01、07-01、10-01、2025-01-01、05-05。所有重叠行与原
2025-05-05 旧单位快照相同，版本末日均不晚于相应发布记录。**这仍是正文抽样，
不是全 702 版本逐日输入认证。** 原两日缺口、Pectra 后错误区间及 ×32 单位
转换结论不改；702 个版本也不等于 702 个独立交易事件。

语义明确为“升级前验证者退出队列数量代理”，不称实际卖出量。
[旧协议的退出／罚没逻辑](https://github.com/ethereum/consensus-specs/blob/v1.4.0/specs/phase0/beacon-chain.md#initiate_validator_exit)
把退出排队与可提款时刻分开，罚没也可以触发退出；
[Capella 提款逻辑](https://github.com/ethereum/consensus-specs/blob/v1.4.0/specs/capella/beacon-chain.md#is_fully_withdrawable_validator)
另检查提款凭证、余额及可提款 epoch。数量乘 32 不代表精确可售余额，部分
提款也不等于退出。允许研究“库存压力是否有预测力”，但尚未证明成本覆盖，
更不能说每个退出者都卖币。
