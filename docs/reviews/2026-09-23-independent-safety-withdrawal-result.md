## 验证失败如何处理

首轮 Linux 55 项通过，第 56 项事务测试失败，63 项未执行。先暂停，确认
Docker tmpfs `/tmp` 默认 noexec：相同临时可执行替身在 `/tmp` errno13，
在隔离构建目录退出0。不是缺 Docker 守护进程，也不是模型或 Bybit 问题。

限定修复 CTest 默认临时目录为构建内私有目录；永久 CMake 模板生成相同配置，
所有原断言保留，两个纯数据 fsync 夹具原 /dev/shm 设置保留。按门禁复盘接受后
唯一原命令复验119/119、96.66秒。随后完成发布前多桶与重报价边界复核并增加
回归，重新构建最终代码，两平台最终通过如上。预检已增加实际执行临时替身。
原失败字节/hash及四份旧 HALTED 原件均保留，没有换 state 或跳过失败测试。
详见[根因与原命令复验记录](2026-09-23-safety-linux-noexec-review.json)。

## 工程、统计、风险多视角复盘

这是内部交叉复核，不冒称外部专家会议。

1. 工程：仅把判断插到统计门槛前还不够，统计选桶也可能使亏损桶得不到评估。
   现用各桶独立固定安全窗口，每周期全部评估并清窗；应用重报价、异步发送、
   持久化与重启均接通，验收不止看控制器日志。
2. 统计：安全撤回不需要证明另一个权重更优，也不改变原候选留出门槛。
   原“总收益增量只是敞口缩放”的结论不变，没有新经济资格。
3. 风险：当前共享净持仓，明确是进程组合保护，不冒充单候选子仓。
   不把 0.4 恢复 0.5 当作减风险；不声称已经送出的请求不会迟到成交。
   写失败靠事前 ARMED 留痕使重启保守关闭，不靠重启清锁。
4. 执行：环境预检必须覆盖“可执行”，而不只是可写、容量和锁；本次遗漏由
   执行者承担，不用修环境无限延长策略研究。现在默认临时目录由 CTest 固定。
