# 三资产相对强弱完整开发方案

2026年10月19日。阶段目标是用一次完整开发批次，判断 BTC、ETH、SOL 的相对
强弱排序能否产生覆盖双腿成本的收益，并判断有限参数选择是否有增量。
不是承诺盈利，不是重跑 BTC 单资产校准，也不把开发通过写成 G4。
用户要求先交付可落地方案并评审，再继续；本方案的市场执行状态为
`PROPOSED_PENDING_SCOPE_DECISION`。本轮只交付设计、只读输入核对和评审。

本提案涉及新的三资产趋势类研究范围。旧单资产周动量、ETH/SOL 回归、
三资产残差及 BTC 条件响应的关闭结论全部保留，不由普通实现授权推定重开。
如果接受这个完整范围，内部取数、实现、测试、一次经济批次、复算和交付
连续完成，不再逐步索权；禁止自动追加第二批。

机器参数见[执行提案](2026-10-19-cross-asset-relative-strength.proposal.json)，
评审及尚未解除的停点见[评审结论](../reviews/2026-10-19-cross-asset-plan-review.md)。

## 为什么是这个问题

假设是同一市场中相对较强的资产，在随后一周相对较弱的资产仍有收益优势。
潜在解释是资金配置和信息反应的延续；反例是共同风险暴露、反转、资金费和
交易成本。这里检验条件关联，不声称识别了真实资金流或因果机制。

[Liu、Tsyvinski、Wu 的作者工作稿](https://economics.yale.edu/sites/default/files/2022-10/LiuTsyvinskiWu2019%20COMMON%20RISK%20FACTORS.pdf)
研究了加密资产横截面排序，提供提出该问题的外部依据。其广泛币种样本、
收益构造及卖空条件不同于本项目；不能把论文收益搬到三个永续合约，也
不能称本方案是论文复现或已有盈利证明。

| 旧研究 | 本次实质差异 | 不能据此宣称什么 |
| --- | --- | --- |
| BTC 周方向延续 | 交易两币相对表现，不按 BTC 自身收益正负开单腿 | 不宣称价格动量首次研究或旧路线已经通过 |
| ETH/SOL OLS 残差回归 | 不拟合均衡价格、不逆偏离交易；从三个币中选相对赢家和输家 | 不能因为旧回归亏损就推断反向必然盈利 |
| 三资产残差与短周期模型 | 周级排序与持有，逐腿完整账户，不复用旧残差信号 | 不证明周期加长本身有效 |
| BTC 成交量条件响应及校准 | 新信息是币种之间的相对排序，不修旧预测分数 | 不把同源价格变换冒充外部独立数据 |

选择三个币是因为已有输入和执行部件可复用，不是因为看过本策略的收益。
它是事后选定的固定小资产集合，不能外推到全部加密市场或声称无幸存者偏差。
等金额多空只减少净名义敞口，不等于 beta 中性、低风险或无资金费风险。

## 策略与有界参数选择

固定币种顺序为 BTCUSDT、ETHUSDT、SOLUSDT。每周一00:00 UTC，对每币计算
`score_i = log(C_i(T) / C_i(T-L天))`，其中C只含T时已结束日线的收盘，
L只允许7、14、28。排名最强做多、最弱做空，中间币不交易。
任意并列最强或最弱时该周现金，不用币名字典序人为产生优势；数值比较
使用原始十进制价格的比值交叉相乘，日志只为解释，不依赖浮点排序容差。

每周入场总名义固定2500参考USDT，每腿1250，初始资本10000，不复利。
在决策时用已知收盘价冻结数量：`q绝对值=floor(1250/C_i(T)/数量步长)×数量步长`，
基础与压力情景使用同一原始订单数量，不用未来成交价反算有利数量。成交价
变化可能使实际名义偏离1250，实际敞口照计。固定数量持有，周内不重平衡。
每个周末周日23:50请求两腿退出，
下一周重新排序；即使币对不变也完整计平开成本。这是有意简化的独立周
持仓政策，不在看到成本后改成跨周续仓。最多同时两腿，上一周期未退出
不得开新周期，不能把未成交的腿按目标价格补记。

| 区间 UTC 左闭右开 | 用途 | 周期数上界 |
| --- | --- | ---: |
| 2024-01-08—2024-07-01 | 三向量开发选择 | 25周 |
| 2024-07-01—2024-12-30 | 选中参数与7日对照冻结开发比较 | 26周 |
| 2024-12-30—2025-01-01 | 只保留账户尾段，不开不足一周的新周期 | 0 |

初始资金在2024-01-01建立，首周仅预热/现金。三个向量都从相同初始状态
开始，但各自承担损益和风险；不能把其资金相加称组合。7月1日按已完成
前25周的 `min(基础净额, 压力净额)` 选一个向量。负收益允许参与，硬停止、
未解释执行不足或未出清者不入选。精确相同优先7日，其后14、28日。

选中向量与固定对照保留现金、风险峰值、资金费状态、告警等完整检查点继续。
同一向量只继续一次，不能在7月1日重置亏损或改回撤起点。所有输入都是
开发；后26周是冻结参数开发检查，不是未消费的独立确认。

最多3项前段成对计算、2项后段续算、2项完整年度延迟敏感性，共7项。
后段与前段是同一账户，不是7条独立实验；正常最多3个初始账户，延迟
最多2个。延迟对照和选中策略都预先列入，以免事后挑一个未测延迟的赢家。

这只是有限参数选择，不是在线自进化。样本只有25个选择周，禁止在此基础上
加入树模型、神经网络、强化学习或继续校准。后续是否值得研究在线更新，
必须先有冻结策略经济支持，不能把本轮3向量选择当成持续学习验收。

## 逐腿执行与风险

复用原双腿账的会计原语，在新文件适配币对，不改旧runner、源码快照或结果。
新规则必须覆盖币对轮换；不能直接假定旧ETH/SOL入口已经支持BTC。

| 项目 | 固定实现 |
| --- | --- |
| 逐腿顺序 | 按固定币种顺序，首腿T+60秒、次腿T+120秒尝试；退出同顺序 |
| 基础情景 | 每笔5.5bps手续费，分钟open加2bps不利滑点及不利tick取整 |
| 压力情景 | 每笔11bps手续费，买用分钟high、卖用low，再加4bps不利滑点及tick |
| 数量步长 | BTC 0.001、ETH 0.01、SOL 0.1；价格tick依次0.1、0.01、0.01，沿用原研究参考，不冒称历史账户规则 |
| 成交与容量 | 数量向下取整；每笔最小名义5；不超过该分钟基础币成交量1%，不足则按部分成交处理 |
| 失败开仓 | 取消未完成部分，下一分钟开始逐腿退出已成交部分；单腿损益和全部费用照计 |
| 退出期限 | 请求后5分钟为最后尝试，仍有残余即执行不足并保留负债；不得虚构出清 |
| 资金费 | 按真实事件时间、该币mark open和当时有符号数量计；同钟先资金费后成交，不翻倍 |
| 延迟对照 | 首次入/出场额外60秒，其余规则和5分钟退出截止不变 |
| 硬风险 | 任一成本账8%回撤、5000总名义上限、逐腿参考抵押耗尽或下述缓冲比不足8%，两账停止新增并退出；永久不重置 |

参考每腿1倍入场名义抵押，不以另一腿盈利抵消逐仓破产。沿用旧零维持保证金
代理：`缓冲比=(该腿抵押+该腿累计有符号现金流+有符号数量×mark)/绝对mark名义`，
空仓不计算该比值；现金流含成交、费用和资金费。这不是实际强平距离或充分的
保证金认证，不得用这一代理授予交易资格。分钟mark不利极值
形成风险情景包络，不能声称多资产极值真实同时发生或8%是未来损失上界。
历史风险档位、真实成交概率与本账户费用仍未认证，本批只是开发账。

沿用新研究规则的性能告警分层：两个连续240个5分钟观察窗口净权益下降
触发告警；本方案始终禁止在线参数更新。告警立即运行确定性数据/账务/执行
复核，下一240观察窗口前未通过则禁止新增、退出并记不足。复核通过可按
原冻结政策继续；两个正窗口后仅清告警显示，不清硬停止或人工禁开仓。
这不是更改现有Demo或已停止的旧研究路径。

独立账必须满足 `净额 = 毛交易损益 − 手续费 − 滑点 − 有符号资金费成本`。
毛额按同一真实模拟数量/时间的未加价minute open计算，high/low及tick差异
归入滑点，不重复扣。终端未平仓估值与退出准备单列，不把估值叫已实现收入。

## 冻结裁决和最终输出

以下是新批次开发投入标准，不替换旧G4门槛，也不声称统计显著。

1. 输入、逐腿账、风险路径和退出完整；正常/延迟账无硬停止、无未解释残余。
2. 正常路径完整账户基础/压力净额均正；后26周基础净额正、压力净额至少100 USDT。
3. 后26周至少20个完整双腿周期、20个活跃周；不足不能说经济被证伪。
4. 后26周前13周和后13周压力净额各正；最大正周占全部正周净额之和不超过35%，
   扣掉最好一周后的压力净额仍正。删周仅账务敏感性，不伪称可执行删单策略。
5. 延迟路径完整账户及后26周两成本均正，风险/执行条件仍通过。
6. 若选中参数非7日，声称学习增益还须后26周基础和压力分别比7日对照多至少25 USDT。

最终选择规则在看收益前固定：若选中非7日且满足全部条件与增益，选该向量；
否则仅当7日对照自身满足全部绝对条件及其延迟条件时，输出固定规则开发支持。
这是在已消费开发集内最多两个对象的预定决策，不是两次独立验证。非7日只是
少亏时不能选；固定对照通过时不为追求自学习再改模型。

全部都不满足时终止，不测试第二名、不反向交易、不改持有期/风险/费用。
结果分为 `INPUT_OR_EXECUTION_INSUFFICIENT`、`NO_GO_RISK`、`NO_GO_ECONOMIC`、
`INSUFFICIENT_DIVERSITY`、`FIXED_DEVELOPMENT_SUPPORTED` 或
`LEARNED_DEVELOPMENT_SUPPORTED`；逐项同时保留原因，不用一个状态掩盖其他失败。

交付一次完整报告和可复算账：毛/净收益、费用、滑点、资金费、换手、总/净
敞口、BTC暴露诊断、最大回撤、退出残余、逐周/分段损益、集中度、延迟差、
选择次数及旧数据使用身份。夏普只报开发估计和依赖敏感性；硬停止或不足
不包装成稳定年化业绩。币对数和分钟数不增加独立周样本量。

## 继续到确认与Demo的条件

开发未支持直接结束，本批不包含等待。开发支持也不直接启动26周观察。
先以26个开发周估计依赖和尾部，给出确认成本表。绝对最小经济效应为
100/26 USDT每周，学习增量为25/26 USDT每周；假设标准差1、1.5、2倍，
周HAC滞后1、2、4全部列示，不能选择最短结果。方差不可靠或收益高度集中
则确认可行性不足，不给精确天数。

单侧5%、目标80%功效的正态近似 `n ≈ (1.645+0.842)^2×长期方差/最小效应²`
只用于规划，不是重尾/非平稳市场的保证。即便独立正态周收益，年化Sharpe为
1、2、3时，检验正均值的量级分别约322、81、36周；它不是本策略预测，
更不能通过改成分钟采样把这些周数缩短。相关性、费用与联合要求可能更不利。

确认前另冻结唯一策略、输入、固定终点、统计方法、最小效应、经济/执行门槛、
运维与最长观察预算；只在固定终点做成功裁决，安全退出可随时触发。所有已见
年份保持开发身份，不用新下载/新文件名制造独立样本。若所需周期不可承担，
交付开发支持但不进入等待，G4仍未通过。

之后才是只读实时信号与执行影子检查，再是需要明确风险决定的Demo开仓。
影子成交不等于实际成交，Demo也不能证明真实市场容量；线上策略身份、账务、
风险及旧资格要求仍须逐项满足。实盘和资金权限不在本方案内。
