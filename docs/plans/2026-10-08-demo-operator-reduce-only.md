# Demo 禁止新增仓位实施与验收

用户在 2026 年 10 月 8 日确认：禁止当前 Demo 新增仓位，保留采集、对账和
风险减仓。随后明确批准对旧 GitHub 发布阻断做一次有界安全控制发布尝试。
这不是研究重启、候选启用或经济资格通过；旧失败与历史证据保持。

## 固定范围与完成条件

输入为本地 main `98e9a02` 和当前 S5 Demo 配置。此前只读运行
`37729408679` 观测到 release `21e8d46`、配置 SHA256
`4051c0f346b3f1f80b71df7197424e993a2d9c38d818ad57cbfee5bd91388b6f`，
没有挂单或持仓，但仍允许旧策略交易。该快照不是持续无仓保证。

实现 `execution.operator_reduce_only`，默认关闭，仅当前 S5 Demo profile 开启。
配置在启动时绑定，普通风控自动恢复不能清除。风险决策、统一下单入口和
异步发送边界都拦截新增敞口；队列排空也不例外。订单用途标签不能代替
交易所 reduceOnly 标记。原止损、止盈、减仓、迟到成交处理与对账继续执行。
复用原启动订单恢复及风险订单撤销，撤单请求不冒充成交已不可能发生。

本批最多 4 有效工程小时，一轮合成及完整本地回归，一次 main 发布尝试，
精确 SHA 的 CI/CD 及一次部署后只读核验。使用独立
`.artifacts/demo-operator-reduce-only-20261008/validation-state.json`，只服务
新批准的安全范围；不重置任何旧 gate。技术失败先诊断，根因确认后按原
协议至多一次同命令复验；发布再次失败则停止发布，不换协议或强推。

通过条件是代码回归、实际部署身份与配置一致、运行日志明确
`operator_reduce_only=true` / `force_reduce_only=true`，服务仍运行、交易
适配器健康，账户检查没有未处理的开仓挂单。有效 `trade_ok=false` 是禁开仓
的预期结果，不改写为健康交易或盈利。线上证据未取得前只能报告本地完成。

## 后续边界

不停止整个服务、不撤销 API 权限、不修改风险阈值或启动新策略研究。
不靠真实试下开仓单测试安全开关。取消禁开仓需要新的明确风险决定，不能
由观察期结束、无仓、冷却结束或普通继续指令自动恢复。
