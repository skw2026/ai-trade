# ETH协议燃烧/净发行输入评审

用户在“下一阶段先核实ETH燃烧/净发行字段与发布时间，再决定是否立项；
本批不追加实验”的建议后明确同意。本阶段开始2026-09-28 14:34:39 UTC。

仅评审R2的输入可行性，连续完成资料、目录/最小样例探测、口径核对、裁决及
main脱敏交付。不复开BTC注意力等旧路线；0回测、收益计算、训练、账户访问、
交易、采购、部署。不能将本次同意扩成另一轮200GET/经济实验。

自限90有效工程分钟、最多40可见公开读取单元，其中真实匿名API/源码GET
最多12次；搜索/open/find每个请求计1，失败也计，工具内部HTTP次数未知。
只获取官方文档、字段目录、历史覆盖/状态元数据及必要最小字段样例（每来源
最多3日），不下载完整信号历史或行情序列，不计算信号容量/持仓收益。

固定核查问题：

1. 执行层base-fee burn与blob burn如何定义，是否计入总供给？
2. 共识层真实奖励/罚没如何定义，存款、提款、验证者小费/MEV不能当新增发行。
3. 免费入口实际包含哪些字段、历史起止与缺失；不能用总手续费冒充燃烧。
4. period_end、链上finality、供应商处理完成、首次发布、修订版本各代表什么；
   固定延迟不能凭空证明point-in-time（历史当时可见）。
5. 在此基础上是否可立项一个“重构数据否定性筛查”，而非盈利/启用资格。

优先官方Ethereum/EIP定义与Coin Metrics Community官方目录/定义；必要时
同一ETH机制内查官方开源实现/公开供给数据替代。无可绑定字段/权限则明确缺件，
不是否定ETH机制；不得因为供应商缺免费字段就伪造数值或扩大成付费采购。

预设出口：INPUT_READY_FOR_RESEARCH_DESIGN（仅可拟下一实验合同）、
PARTIAL_INPUTS（明确未解字段/时点）、或NO_FREE_INPUT_PATH_CONFIRMED。
正向裁决不要求先证明盈利；首发版本若未知须区分重构否定筛查与真实PIT资格，
不能借未证明盈利拒绝研究，也不能假装时点证据已经完备。
