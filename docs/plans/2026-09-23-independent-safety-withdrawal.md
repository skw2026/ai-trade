# 独立安全撤回：事前工程合同

用户于严格组合批次 HALTED 后明确选择“独立安全撤回”。本批是新增风险语义的
独立实现，不是旧 Linux 验收的第三次重跑；四份旧 HALTED 状态与失败原件不改。
工程投入自限最多 8 有效工程小时；每个失败按验证协议诊断、原命令一次复验，
连续两次未解决或结构性不可达先完整路线复核，不自动续预算。
新 gate：`.artifacts/safety-withdrawal-20260923/validation-state.json`。

## 固定语义

- 统计调权与安全撤回分离。显式 `safety_withdrawal_enabled` 开关默认 false，
  本批不修改现有线上策略 profile、不激活市场候选。新增语义在隔离组合验收启用。
- 沿用现有评估周期、退化窗口数和 objective 阈值；仅有实际损失的有效窗口
  （所选 PNL < 0，且 objective <= 现有阈值）计为退化。虚拟模式须有价格收益
  样本；已实现模式须有实际 PNL 变化。无活动/零收益不算损失；正收益清除该桶连续计数。
  安全检查先于 learnability、留出、相对改善、更新间隔等统计候选门槛。
- 任一桶达到连续退化阈值即全组合锁存：停止调权，不恢复基线，不因更换桶、
  等待冷却、重启、换配置/二进制而解除。当前共用净持仓，作用域明确为本进程
  的自适应组合，而非虚构单候选子仓、交易所账户级开关或其他进程。
- 保留已有减仓、止损、止盈与硬风控。入队和异步发送边界都拒绝非 reduce-only
  委托；已发送且不可追回的在途请求不能声称“零成交”，必须取消本进程的未终结
  加仓单并继续对账迟到成交。撤单失败保持锁存，不伪造取消确认。
- 持久日志独立于权重/政策指纹，写入与目录同步；会话先记 ARMED 再允许风险。
  异常退出、截断/损坏、写入失败重启均 fail-closed。正常无锁存退出才可记 CLEAN；
  没有 clear/unlock API，恢复必须另经原资格和明确恢复流程，不能以重启代替。

## 固定验证与交付

1. 先检查依赖、容量、可写锁/临时目录，使用仅源码/测试夹具的隔离可写工作副本；
   不给真实账户资料或原证据写权限。本地固定旧模型只读复用，不训练、不下载市场数据。
   CI/CD 保持既有固定合成训练回归，追加同模型安全检查，不开展新的市场研究。
2. 覆盖严格不足样本/无改善仍可安全撤回、非损失不误触发、同事件入队、异步队列、
   未完成撤单/迟到成交、跨桶/冷却/重启/损坏/写失败、保护单保留、旧模式不变。
   真实 CatBoost 原模型退化路径必须触发独立撤回，正常路径仍受原严格门槛。
3. 完整本机与 Linux CTest，新增测试纳入 CI/CD 完整回归。通过后按持续授权提交
   main/push，跟踪精确 SHA CI/CD 和部署后收据。旧 V4 唯一超时身份仍真实 FAIL，
   Archive 仍可证据不足；新增未知错误/缺件仍暂停。无直接账户操作。
4. 交付只证明新增风险处置的工程行为。不得称市场策略合格、盈利、自学习全目标
   完成；本批没有自动恢复/重新晋升权限，也没有默认两周等待。
