# 原 MVP 人工风险周期：确认后的固定实现合同

用户确认“仅人工批准新风险周期，永久保留累计损失和历史最大回撤，禁止自动解锁”。2026-09-21 13:21:37 UTC 续接同一 4h 限定改造；前段按 25 分钟保守计入，等待回复不计为工程工作。仅本地源码、合成测试与归档，不访问账户、不交易、不部署、不提交推送、不自动启动历史实验。

## 在测试结果之前固定规则

1. 仅 `closed_bar_mvp` 离线模式使用人工周期层；既有 Demo/legacy 行为和运行配置不变。原 8/12/20% 风险动作保留；12% 冷却与 20% 熔断一旦触发，不能靠等待、行情回升、断连或重启自动解锁。
2. 初始周期继续以原账户高水位衡量。新周期只重建**周期**权益参考，不写账户现金、累计盈亏、费用/funding 或原账户高水位。另记全生命周期 peak/MDD 与永久的 20% 触线事实；人工恢复不能让旧周期或整段历史变成资格 PASS。
3. 新周期条件：当前账户全平（尘埃也不能被忽略成授权）、全部订单终态、通道健康且无强制只减仓，连续满足条件的模拟时间至少 24h。批准必须绑定当前周期序号、当前观察时间、唯一批准 ID 和非空复盘引用。没有审批调用/文件标志就永远不恢复；此实现不会自行生成批准。
4. 人工批准必须显式给出名义上限与最大损失金额。上限不能超过原账户 gross cap；损失金额不得超过新周期起始权益的 2%。该 2% 是恢复期的附加保守上限，不改原阈值、不是收益选择出来的参数。达到起始净损失或峰值回撤金额预算、原 DD 锁存线、7 日周期到期，任一即全平锁存，需新的复盘与批准。跳空可超过预算，预算是触发线而非损失保证。
5. 分段为批准上限的 25% → 50% → 100%。每段至少 24h，升档仍需新的人工批准、全平/无待单/健康；不因时间自动升档，不允许跳档、重放批准、改变同周期预算或延长其到期时间。健康/订单/全平不满足会重新开始冷却观察。
6. 持久化先于批准或风险状态生效，追加且 fsync，保留观察和批准记录。新模式应用必须使用独占新 journal；已存在 journal 的重启拒绝运行，不能因为 replay 旧 WAL 默认不恢复而清空风险。**本轮不实现行情游标/策略/账户的完整断点续跑，也不冒称有该能力。** 所有历史财务与风险记录留在旧 journal；换目录不能算恢复同一资格对象。
7. 人工周期 API 仅供受控离线调用，不是人的身份认证系统或线上运维界面。当前聊天确认授权实现规则，不是任何实际账户/具体亏损周期的恢复令。

补充执行约束（同一工程审查内、历史实验之前）：新离线模式存在任意 symbol 在途订单时只允许减少风险，不把未成交的减仓当成已释放额度；锁存后下一次 open 前撤销所有待成交入场单。恢复验收必须实际产生一个被 25% 上限裁剪的非零决策，不能以一直无交易假通过。

## 验收与停止出口

- 合成 13% / 21% 损失后空仓推进至少一周，无批准仍锁存；人工恢复后旧账户高水位、净损失与 MDD 不变。
- 过早/过时/重复/错误周期/缺引用/过高预算/持仓/在途订单/通道异常/强制只减仓批准均拒绝，拒绝不得改变周期。
- 准确边界验证 24h、25/50/100、2%损失、7日到期、再熔断；普通账户 gross cap 和未知强平信息保护不能被恢复绕过。
- 新模式完整应用创建持久记录，再用同目录启动必须拒绝；已有文件不覆盖。存储失败不得产生放行状态。
- 定向通过后全量 CTest；所有正式构建/测试经原验证门禁，失败暂停、确认根因后一次原命令复验。
- 完成后仅判断合同是否足够进入历史数据/资本/成本入口审核；不以工程 PASS 放行经济资格，也不新增 alpha 路线。
