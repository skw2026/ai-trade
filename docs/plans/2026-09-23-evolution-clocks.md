# 自进化评估/更新时钟解耦（事前合同）

用户在上一阶段结案和明确下一优先项后要求自动按计划落地。本批完成该工程项的
实现、确定性验证、真实学习链回归、main发布及部署后收据，不再逐步索权。
限定4有效工程小时；不续旧研究预算。沿用已READY的离线工程gate历史
`.artifacts/offline-learning-loop-20260922/validation-state.json`，标签区分本批；
新产物写入`.artifacts/evolution-clocks-20260923/`，不改旧产物或HALTED状态。

## 固定通过条件

- `update_interval_ticks`只控制评估；`min_update_interval_ticks`是全局实际调权
  下限，包含首次启动等待。不按bucket轮换绕开下限；无变化不算成功调权。
- 原有充分样本/learnability/反事实holdout门槛不放宽。正常调权受下限约束，
  已符合原回滚条件的退化窗口仍每个评估周期检查，不因更新限频延迟。
  原strict temporal-holdout分支的回滚政策不改。
- 退化回滚优先于普通更新限频，回滚后保留原冷却；期间继续评估、禁止调权。
  权重非负/和为1、步长和上限不变。
- 新增显式`clock_tick_interval_ms`：0保留行情计数兼容；正数使用事件时间计算
  逻辑tick。测试固定300000ms，12/72/288分别对应1h/6h/24h。
  相同时间的多币种消息或高频消息不能加速时钟；缺失/倒退时间不推进状态；
  大时间跳跃最多做一次真实窗口评估，不补造空窗口。时间模式从首个有效事件
  起步，或测试显式指定起点。不是无行情时仍运行的后台墙钟调度。
- 新确定性测试覆盖启动、正常限频、跨bucket、无变化、回滚/冷却、事件突发、
  缺失/倒退时间及时间跳跃。保留完整旧回归与真实模型六组验收，合成数据、
  模型超参、费用、收益判据不改；仅增加计时审计断言，不要求旧动作次数不变。
- 真正的训练/推理/账务链仍须在Linux断网容器中通过；源SHA、镜像与部署后
  回执一致。旧V4已知坏段真实FAIL、Archive仍证据不足；不追溯PASS。

## 范围和停止条件

不改正在运行的策略配置、不切换Demo/live、不访问新账户、不启用候选、不恢复
研究cron；显式时间模式的生产配置启用不冒充本次已观察到的线上小时行为。
本批交付的是已接入应用、可配置且实测的计时能力，而非完整生产自学习资格。

正式验证经原gate；预期负例在测试中断言。意外失败先暂停依赖工作，确认根因、
复核路线后限定修复及一次原命令复验；第二次未解决或结构性问题重审路线。
发布观察命令使用稳定入口读取明确的发布身份，不再把不可变run硬编码为验收合同。
