# AI Trade：由 AI 实现、按结果验收的实施计划

状态：执行中。依据用户最新要求，不以工作日、运行时长或累计轮次衡量完成。

本计划替代[旧时间排期](2026-09-05-evidence-first-delivery-roadmap.md)的执行安排，不修改旧 v2 冻结实验的原有统计合同。市场事件时间仍是数据和收益计算的必要输入，但不是阶段完成标准。

## 推进规则

- AI 负责读取证据、实现、反例/回归验证、提交与检查；普通实现步骤不反复要求用户排任务。
- 一次交付一个可验证成果；上一门未过，不用新增功能掩盖失败。
- 金融语义与实现冲突，先复盘定规则，不通过调低阈值或伪造风险数据过测试。
- 仅账户/产品风险边界、付费采购、资金与交易授权等实质决策需要用户确认。
- 未取得新授权前，保持原逐仓及禁用新 Demo/live 的边界。
- 等待仅用于缺少不可替代的事件/样本；必须说明缺什么、满足什么条件可以继续，不能只说“再等若干天”。

## 结果门禁

| 门禁 | AI 要实现的成果 | 验收出口 |
|---|---|---|
| R1 风险保护语义 | 危险仓位不被加权掩盖；未知风险不放行；Fuse/Cooldown 不被弱保护覆盖 | 原实现反例失败、修复后反例与回归通过；发布验证独立记录 |
| R2 历史数据资格 | 原生格式解析、真实样例、哈希证据、连续覆盖与缺项清单 | 样例格式通过只代表子项完成；完整数据/费用/交割缺项未清零不能回测晋级 |
| R3 完整研究账务 | 实际 funding、期权/hedge 现金流、净值、保证金、持仓生命周期、数量与时序 | 手算、真实样例、故障反例一致；不再把名义 bps 当账户收益 |
| R4 经济候选资格 | 固定因果基线、成本上界、未见历史、尾部与资本压力 | 正确成本和风险下具备继续价值；否则关闭当前合同，不换名调参 |
| R5 前向迁移 | 新冻结候选的实时完整账与可执行性证据 | 满足预注册有效样本、统计和迁移门；输入不足不能早 PASS |
| R6 Demo 固定策略 | 获批账户上的真实成交、funding、净值及故障处置 | 实际经济/风险/完整性合格；模拟行情不能冒充 Demo 成交 |
| R7 自适应增益 | 相同资本、成本与执行条件下 adaptive/frozen 配对 | 增益可信才启用；无增益保留固定策略，不能伪称自进化成功 |
| R8 实盘评估 | 历史/前向/Demo、风险、容量和资金上限证据包 | 用户独立批准；不自动交易 |

结果类型统一为：通过、经济否定、技术无效、证据不足、授权待定。后四类必须说明原因及恢复条件，不能全部汇总成 WAIT。

## 已开始实施

- R2 子项：已实现 `tools/audit_option_historical_sample.py`，只请求公开免费首日的一分钟、最多四个明确 BTC USDT 期权；无需 API key，禁止付费日期与全市场无界下载。
- 真实样例：同一 strike/expiry 的 call/put 共 301 条合格观察，零拒绝，`PASS_SAMPLE_SCHEMA_ONLY`。连续历史和收益资格均为 false。
- R3–R8 未宣称完成；旧 v2 的 funding、完整 NAV/margin、持仓跟踪等缺口仍保留，不能被 R1 的测试成功覆盖。

具体证据与发布状态见 [首批结果报告](../reviews/2026-09-05-result-gated-foundation.md)。

## 需要用户确认的产品边界

原合同要求逐仓，而当前 Bybit USDT 期权不支持逐仓。已询问是否允许设计独立子账户、限定资金的期权风险合同；这不包含切换账户、划转资金或启用交易。没有确认前，不放宽原边界。

## 每次交付的报告格式

1. 完成了哪个结果门或子项。
2. 对应代码、测试、真实输入与不可变身份。
3. 数据、金融语义、经济证据、部署与交易权限分别是什么状态。
4. 未通过项及确切原因。
5. 下一项可实现结果，或必须补充的数据/授权。

不再以“已工作几天”“累计运行多少小时”或代码量作为进度结论。
