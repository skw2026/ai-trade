# Aave 清算伴随现货出售的残余传导研究

用户明确要求「重新立项新机制研究」。本批唯一对象为 Ethereum Aave V3 的
WETH 清算伴随同交易 DEX 净 WETH 出售，检验事件可知后 ETH 永续是否仍有
费用后的下行延续。先检查真实输入，合格才冻结并执行一次开发筛查；不要求
事先证明盈利，不把研究许可当作 G4、Demo 或实盘资格。

## 为什么是新的问题

本地查重确认，周频趋势和 Bybit SOL 秒级强平信息集已经研究，不纳入替补。
Aave 的抵押信用合同和 DEX 实际交换是此前未登记的输入路径，不是只改币种
或持有期；两者仍同属杠杆去化现象，不能声称经济上完全无关。

[BIS 工作论文 1062](https://www.bis.org/publications/working-paper-1062-systemic-fragility-decentralised-markets)
的官方摘要描述清算者偿还闪电贷时出售抵押品，观察到链上及随后链下的价格
影响，支持提出假设。[加拿大央行 2026 年研究](https://www.bankofcanada.ca/2026/04/staff-analytical-paper-2026-13/)
的官方摘要则认为 Aave V3 清算波次对更广市场影响有限，是重要反证。
两者均非本项目收益证据；本轮未读取论文全文，不借摘要移植参数或效应量。

清算折价归清算者，不归本项目的 ETH 永续空头。我们只能检验已公开事件后
尚存的传导，承担反弹、成本与共同市场风险。清算内生于跌价，不称外生冲击。

## 第一道实际输入检查

[官方 Pool 接口](https://github.com/aave/aave-v3-core/blob/master/contracts/interfaces/IPool.sol)
将 `LiquidationCall` 的抵押品、债务资产、偿债量、抵押转移量、清算者和
receiveAToken 分开记录；仅此日志不能证明出售。Ethereum Pool 地址按
[官方地址簿](https://github.com/aave-dao/aave-address-book/blob/main/src/AaveV3Ethereum.sol)
限定为 `0x87870Bca3F3fD6335C3F4ce8392D69350B4fA4E2`。

先用 [PublicNode 公布的匿名 RPC](https://ethereum.publicnode.com/)
`https://ethereum-rpc.publicnode.com` 做至多六项不同只读控制，每项一次：

1. `eth_chainId` 应为 Ethereum 1。
2. finalized 区块头，核格式及时间；不是输入容量证明。
3. 固定历史区块 20,000,000 的头。
4. `web3_sha3` 对官方事件签名计算 Ethereum Keccak topic，不用 NIST SHA3 代替。
5. 固定区间 20,000,000—20,004,999 的 WETH 清算日志；此圆整区间为访问控制，
   不是根据价格挑选的评价区间。空结果不能证明整个历史没有事件。
6. 若有日志，取按 block/transaction/log 顺序第一笔的完整 receipt，核同一身份。

每次保留请求、UTC 接收时间、原响应和 hash；不得用当前索引器时钟冒称当时
首次可知时间。首次非预期失败停止依赖步骤；剩余额度只作有界只读归因，
不对同一请求盲重试，不把 API 通畅当完整历史或资金流识别成功。

## 输入通过后的经济合同要求

只有完整历史请求清单可以装入剩余 60 次预算，且存在可检验的交易回执，才
在读取 ETH 收益前写定经济合同。清算与 DEX 净 WETH 出售同 tx 是必要关联，
不是逐单位证明卖的正是清算抵押品：闪电贷、旧库存、多路径、同时回购和
多次清算必须核清；归因不唯一记 UNKNOWN，不拿转账量或清算量替代售出量。
DEX 池身份和 token 次序须验证，同 tx/同块去重，并合并连续事件簇。

评价完整固定时间域和事件容量须收益前确定。每次 receipt、区块、池映射、
trade、mark、funding 都进入请求清单。覆盖不足不补热门暴跌日，不扩日期。
无法在预算内取得完整输入时直接 `INPUT_NOT_FEASIBLE_WITHIN_BUDGET`。

方向固定为事件后的下行传导，不因收益翻成反转。候选参考为区块后 60 秒再
到下一分钟边界入场、持有 5 分钟；在正式经济合同前不能运行收益。区块时间
不是历史接收时间，这只是开发延迟假设；最终确认仍需真实接收/最终性证据。
必须有零仓对照和仅用事件前价格/波动/时段的固定对照，不能按事后收益匹配。
低换手不证明有优势，不能将已经出售的量描述为未来必定继续出售的库存。

固定规则通过也只代表机制开发支持，`learning_gain=NOT_EVALUATED`；本轮不为
凑「自学习」临时增加 EWMA、网格或学习臂。开发使用已消费或独立性 UNKNOWN
的行情须明示，不能重新命名成独立确认。真实资格仍需成本后支持、学习增益、
执行一致性及拒绝/撤回/回滚，不把新门禁通过当 G4 或修改旧统计门槛。
