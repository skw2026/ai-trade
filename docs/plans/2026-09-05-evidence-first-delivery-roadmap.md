依据：[项目目标与效率复盘](../reviews/2026-09-05-project-goals-finance-econometrics-roundtable.md)。本计划承接其中已经核实的缺口，不增加盈利预测。

本轮仅新增计划文件；没有修改运行代码、冻结配置、数据、账户、部署或调度。历史 v2 的机器决策与观察时钟不因本计划改变。

## 1. 要交付什么，而不是要连续运行多久

按优先级交付：

1. 能正确计量、能拒绝不可信输入、风险边界明确的研究基线。
2. 在明确资本与成本约束下，值得继续投入的固定策略；否则及时关闭该路线。
3. 历史结论能够迁移到当前报价、执行与账户条件的证据。
4. Demo 实际成交账上的净收益与风险结果。
5. 自适应相对固定策略的可验证增益；若无增益，保留固定策略。
6. 前述条件成立后，形成小额实盘评估材料，由用户另行决定是否测试。

不把 CI/CD 成功、训练完成、更新次数增加、满 35 天或没有成交事故，当作盈利验收。

**节奏承诺：第 5 个工作日前作出研究资格判断，第 10 个工作日前作出路线去留决定。** 不是承诺该期限内证明盈利；遇到关键输入缺失时，结论可以是有条件暂停，而不是无限 WAIT。

## 2. 时钟、预算与权限

### 2.1 三种时间分开记录

- **D1、D2……：项目实施工作日。** 从用户确认执行后的启动日计算；启动时记录绝对日期。预算是上限规划，可以提前完成，不为凑天数等待。
- **F0、F+7……：新候选前向自然日。** 从候选、数据与统计合同冻结且前检通过后开始，不从今天开始。
- **M0、M+7……：Demo 自然日。** 从获准启动、账户核验及第一段合格观察开始。Demo 的盈利证据必须来自 Demo 成交账。

另列“依赖等待天数”：报价、采购、账户选择、数据交付等不能隐藏在技术进度里。依赖未到，D5/D10 仍作阶段决策，不自动顺延；超期需说明新增投入能获得什么信息，并明确批准或暂停。

### 2.2 本计划不扩大既有权限

- 不使用 Keel；不新增 PR 流程。
- 获准实施后，仍按既有直接提交 `main` 的协作方式，小批次提交并完成对应 CI/CD/Smoke 验证。当前“给计划”不触发 push 或部署。
- 数据购买、预算增加、账户模式变更、资金划转、启用期权 Demo、实盘测试均设独立批准点。
- 风控、安全检查和学习模块相互隔离；不能为了新产品落地暗中放宽原逐仓或风险约束。
- 不默认存在后台自动执行或定时汇报。本计划的检查节奏在实施阶段配置并验证后才算启用。

并行规则：

- G1 可与 G0 并行；G2 中无争议的测试和事件接口可提前准备，涉及产品/账户的实现等待 G0 决定。
- 先用数据样例完成 G2，不为构建完整历史仓库阻塞所有工程验证。
- G4 期间可以完成 Demo 接口、只读对账和故障演练准备，但不能提前发单。
- Demo 开始后，公共行情前向观察继续，不额外重启一个相同的 35 天等待期；两类证据分开统计，不能重复计数。
- 单一主要经济机制。简单基线之外，只有通过结构经济性门后才允许最多一个有明确假设的增强候选；不并行搜索大量模型。

以上窗口是资源治理预算，不是统计充分性的保证。G0/G3 必须先估计目标效应所需有效样本量；若所需证据明显超出预算，先决定缩小研究目标、购买合格历史或暂停，不能启动后才发现永远等不够。

按每周约 5 个实施工作日、数据与批准及时到位、各门通过且无需 G3b 估算：约第 4–6 周进入 Demo 启动评估，约第 8–10 周完成首轮 28 天 Demo 复核。G3b 或外部等待另计。这是条件排期，不是盈利、统计充分性或实盘日期承诺；不合格路线应在 D5/D10 或更早结束，而不是被动走完整条时间线。

## 4. 第一阶段：G0 目标和风险合同（D1–D2）

### 要完成的决定

1. 是否坚持逐仓硬约束。若坚持，不再把当前 Bybit USDT 期权作为待落地候选；若考虑专用期权账户，先明确隔离资金范围、Cross/Portfolio 风险合同及用户批准边界。
2. 区分“固定策略可盈利”“自适应有增益”“可实盘”三个目标；后一项不反向强迫前一项通过。
3. 明确研究资本、报表币种、融资/资金占用假设、基准收益与最小可执行数量。没有资本定义，不报告账户回报率。
4. 明确 Sharpe、MDD、尾部、成本、缺失数据和执行失败口径。
5. 给研究数据、计算、存储和人工投入设置预算上限；金额由用户确认，不自行购买。

### 拟定的指标合同

| 指标 | 计划采用的口径 | 约束 |
|---|---|---|
| 净收益 | 账户份额净值，剥离入出金；计入适用费用、funding、融资及退出成本 | 现有名义本金 bps 仅作研究诊断 |
| Sharpe | 日度超额净收益；披露相关性修正、不确定区间和选择次数 | 1.0 作为候选研究参考，1.5 为更高目标；不是现有能力预测 |
| MDD | 指定观察期的账户净值峰谷回撤，同时报告持有期可清算价值 | 原 8%/12%/20% 风险动作不自动改动；20% 不等于损失保证上限 |
| 尾部 | 最差日/周、ES97.5 及跳跃/IV/流动性/断连压力 | 样本不足显示不可估计，不填 0 |
| 可执行性 | 报价时序、数量、手数、费用、拒单、多腿完成与故障动作 | 有 BBO 价格不等于可成交 |
| 自适应 | 相同时间块、资本、成本和执行路径的净增益 | 不能以内部 Sharpe-like、IC 或更新频次替代 |

通过标准与经济吸引力分开：例如 Sharpe 点估计高于 1，不足以单独晋级；必须同时满足完整现金流、风险约束和独立净收益证据。具体样本量、显著性方法及最小有意义效应在观察最终验证结果前冻结。

### 交付与停止条件

- 交付一份 `目标—指标—数据—计算—门禁—权限` 对照表，以及需要用户决定的选项说明。
- 不兼容的产品/风险约束在本阶段停，不等待 35 天；不得把“需要更高风险权限”包装成技术修复。
- 用户决定未到，可以继续不依赖该决定的数据样例和确定性检查，但不执行有争议的账户或风险改动。

## 5. 第二阶段：G1 数据资格（D1–D3，最迟 D5）

### 最小样例验收

1. 优先核实同场所 BTC USDT 期权的连续历史；USDC 历史或其他场所数据只能在明确标注的机制研究中使用，不能直接拼接。
2. 验证历史 instrument、strike/expiry、交割币种、数量与 tick 单位、手续费规则变迁。
3. 验证报价及数量、交易所/接收时间戳、Greeks、持仓全生命周期，以及断流和缺失说明。
4. 对齐 hedge BBO/深度、实际 funding 结算及期权 delivery price，避免仅靠当前 ticker 补历史。
5. 与自采重叠片段做字段与语义对照；免费月初散点样例不能冒充连续回测样本。
6. 建立覆盖矩阵：时间、产品、报价/成交/Greeks/交割/funding、缺失、可用角色。
7. 获取授权条件、完整数据价格、规模及接入估算；先验样再决定购买。

历史时间跨度以合格覆盖为准，优先包含多个波动和方向状态；不因供应商声称提供三年数据就假定当前产品有三年可比证据。

### D3/D5 必须得到的结论

- `DATA_QUALIFIED`：有满足最小要求的实际样例和明确连续交付方案。
- `DATA_CONDITIONAL`：缺少哪些字段、成本和补齐截止时间明确，需用户决定是否投入。
- `DATA_UNSUITABLE`：当前来源无法回答目标问题，暂停该数据路径。

数据不合格不继续建设大规模训练架构；没有完整历史时可继续有限自采，但必须标为重新选择的时间/预算方案，不能默认沿用无期限等待。

## 6. 第三阶段：G2 最小完整研究内核（D2–D5）

只建设验证经济机制所必需的离线内核。尚未证明经济性之前，不建设完整期权生产交易平台。

### 工作包 A：风险语义

- 重定义危险仓位保护：单仓最小距离、危险敞口比例、下尾统计与未知数据状态。
- 覆盖反例：增加安全仓位不能解除原有危险仓位的保护；不能把风险数据未知当安全。
- 明确期权 Delta/Gamma/Vega、跳跃与保证金之间的关系；Cross/Portfolio 不能套用逐仓强平距离概念。
- 独立核对告警、降风险、只减仓和熔断的优先级，避免一个保护状态遮蔽另一个更强动作。

### 工作包 B：完整账务和资本路径

- 按实际时刻计入 option、hedge、funding、交易/交割费用及适用融资成本；统一正负号与币种。
- 资金费覆盖正/负费率、long/short、跨结算持仓、结算附近开平仓、费率频率变化和重复事件。
- 保存账户余额、未实现损益、期权负债、保证金余量及保守可平仓价值；分开 mark 风险和可执行退出估值。
- 输出逐项现金流恒等式与资本约束，不以期末对冲余额为零代替持有期风险检查。
- 实际成本和压力成本分别报告，明确 daily option 交割费豁免与保守扣款的区别。

### 工作包 C：全持有期与执行语义

- 明确最后半天是否继续对冲；选择属于新策略合同，不能根据既有亏损事后改旧规则。
- 新开仓候选筛选与已持仓合约持续跟踪分离，不因 DTE/moneyness 越界丢失风险观测。
- 对每个预定对冲检查点核验输入与迟到；缺失时走已声明的 hold/reduce/invalid 分支，不偷偷跳过。
- 校验 BBO 数量、最小手数、报价可用时间及延迟；两条期权腿不能假定无时间差原子成交。
- 明确故障期间的仓位与资金费延续；缺样本不能把持仓风险从结果里删除。

### 工作包 D：证据和报表

- 旧 payoff 输出不改；新口径使用独立 ID/manifest 和适用范围。
- `complete` 拆分为数据完整、账务完整、执行假设合格、风险可计量和经济门禁状态。
- 最低验收包括手算账单、真实样例、反例和故障状态；既有测试仍通过，但不以测试数量证明设计正确。
- 若确实修改运行代码，按影响范围运行定向测试、回归、CI/CD/Smoke 和部署后金融语义核验。研究 STOP 是业务结果，不当 CD 故障修复。

### G2 通过条件

复盘确认的资金费遗漏、强平距离方向、对冲时间线缺口、零数量盘口及净值缺失均有确定语义和可复核结果。任何一项未解决，D5 结论为“研究资格未通过”，不能把新增运行天数计作新策略盈利证据。

## 7. 第四阶段：G3 历史决定性筛选（目标 D6–D10）

### 固定实验顺序

1. 冻结数据来源、时间区间、适用产品、成本、资本、动作及实现身份。
2. 按时间划分 development、selection 和最终未见验证区间；标签重叠时 purge/embargo。既有用过的 split 不重新命名为未见样本。
3. 先运行无模型乐观经济上界。上界仍不能覆盖成本或资本约束时停止该合同，不进入模型筛选。
4. 上界有余量后验证因果、固定、可执行基线，并包含不交易控制。上界通过不等于策略可实现。
5. 分析收益来源、成本拖累、方向/波动状态、成交与缺失选择偏差，以及最差区间。
6. 做条件压力：价格跳跃、IV 跳变、价差扩大、funding 不利、对冲中断和保证金提高。场景幅度与验收标准提前声明，不能看结果后放宽。
7. 若基线成立且有明确瓶颈，才申请一个增强模型或控制规则；选择只用 development/selection，不能消耗最终验证集反复挑选。
8. 最终输出净值、完整成本、Sharpe/区间、MDD、尾部与资本结果；统计不足明确标记，不只给汇总均值。

不机械沿用“每个到期日独立”的假设；根据相关性与标签跨度确定区块。所有尝试记入研究账本，不能通过更换模型名或合同 ID 清零失败预算。

### D10 的三种项目决定

| 决定 | 必要依据 | 后续 |
|---|---|---|
| 继续 | 数据和语义门通过，因果基线显示经济余量，风险可接受，最终验证/前向预算可行 | 冻结候选，进入 G4；未补齐部分仅可申请有上限的 G3b |
| 转向 | 原路线明确不符合成本或产品约束；替代方向有实质不同输入与资格依据 | 先圆桌复盘和批准新范围，不自动开新族 |
| 暂停/关闭 | 数据不经济、上界失败、风险不兼容，或有效证据所需投入超过预算 | 保存证据，停止该路线的训练与反复 full loop |

若数据直到 D5 才到位且完整分析需要额外时间，D10 仍应基于已完成资格和初筛作有条件的预算决定，不能称完整历史验证已通过。最多一次 G3b，须说明具体缺口与可证伪目标。

## 8. 第五阶段：G4 新候选前向迁移（F+14–F+28 预算）

### 启动门

G0–G3 合格；候选、来源、样本/统计、持仓、成本、风险和故障合同冻结；容量与保留窗口足够；所有自动激活权限仍关闭。若预计样本不能在预算内支持所需判断，在 F0 前重新决定，不先开跑再无限延期。

### 观察节奏

- 每个到期/结算事件后：更新完整现金流、暴露、资金费和数据缺口；这是诊断，不自动调参。
- F+3：检查输入、生命周期和财务口径是否与历史一致；不作盈利晋级。
- F+7：迁移复核；依预注册规则可停止明显不合格路线，不能随意从每日查看中挑成功日期。
- F+14：第一次预算去留会；经济正式结论仍按 F0 冻结的样本量与检验方案。
- F+28：初始预算最终复核；通过、停止或有明确新增信息价值的延期申请，不能自动续 28/35 天。

这组日期是项目复核点，不是新统计门槛；不会替换旧 v2 的 Day8/14/21/28/35。新候选的提前通过/停止是否允许以及如何控制检验误差，必须在 F0 前写清。

### 通过门

- 原始到报表可重放；没有尚未解释的账务、时序、数量和风险数据缺口。
- 冻结的成本后经济门、有效样本门与尾部约束同时满足；不以工程 pass 替代。
- 实际 forward 与历史假设的费用、暴露、缺失和机会差异在预先声明的范围内。
- Demo 的产品支持、账户模式、资金预算和风险接口已核验。若目标产品没有合格 Demo 执行环境，报告为新的落地阻塞，不能以实盘替代测试。

## 9. 第六阶段：G5 Demo 固定策略（M+28 初始预算）

### 启动前

需要单独批准：账户、模式、资金范围、策略数量、仓位与损失预算。限定目标账户；核验权限、对账、行情与资金费记录、幂等、重启、断连、保证金预警及紧急停止。不得通过切换现有账户模式规避 G0 决定。

在 M0 前声明未成交通知、部分成交、撤单、对冲失败与未知仓位如何处理。公共报价回放仅作对照，不计成 Demo 收益。

### 时间安排

| 节点 | 重点 |
|---|---|
| M+1–M+3 | 最小批准风险预算，逐笔核对成交/费用/funding/余额及风险状态；不以盈利评判联调 |
| M+7 | 成交偏差、缺失、拒单和故障处置复核；若账务或风险有缺口，不继续增加敞口 |
| M+14 | 第一轮实际净收益与风险偏离评估；正常小样本亏损不触发事后调参 |
| M+28 | 初始预算去留决定；没有经济支持不得自动延期 |
| M+56 | 仅在 M+28 有明确依据、用户批准延长后才适用；作下一阶段或停止决定 |

### Demo 验收

- 每笔交易、资金费与账户净值可对账；不把不存在的成交填入报表。
- 执行偏差与风险处于冻结预算；已演练关键故障，不仅观察“暂时没出事”。
- 实际净收益、回撤和尾部符合事先合同，样本/统计资格足够；持续期长短不能替代证据。
- Demo 成交机制与实盘差异单列：Demo 通过不证明实盘流动性、冲击和清算行为相同。
- 没有通过前，不进入真实账户；不能为了获得更真实数据提前实盘。

## 10. 第七阶段：G6 自适应增益与 G7 实盘决策

### 自适应必须晚于固定基线资格

固定基线合格后，可并行跑 shadow 自适应，不改变 Demo 当前动作。配对实验使用相同市场区间、资本、成本、执行与风险模型，唯一必要差异是自适应规则；虚拟结果不能冒充真实成交反事实。

- 预先固定更新频率、候选数量、目标函数、预算及样本量。
- 比较净增益、换手成本、尾部和回撤；内部奖励不能替代外部净值。
- shadow 证据合格后，如需影响 Demo，另设受限验收窗口，不能直接影响 live。
- 初始评估预算不默认超过 28 自然日；若功效估计明显不够，开始前决定研究目标和投入，而不是到期继续等。
- 无可靠增益，交付固定策略并关闭本轮自适应候选；不为完成“自进化”标签无限加模型。

### 实盘不是本计划自动终点

满足用户要求的 Demo 经济与风险验收后，提交实盘评估包：

1. 独立历史、前向、Demo 三类证据及不可互相替代的局限。
2. 成本、账户净值、Sharpe/区间、MDD/压力、margin/清算和尾部风险。
3. 适用市场状态、容量、允许仓位与最大资金投入。
4. 明确停止、降风险、回滚及人工接管条件。
5. 已知未覆盖风险，尤其 Demo 与真实成交的差异。

资金金额、最大损失和实盘启动由用户另行批准；不得把 read-only 或 Demo 凭据升级为真实交易授权。固定策略可以先达到工程交付，但若用户坚持自适应也必须合格，则其未通过时不能越过该要求申请实盘测试。

## 11. 旧 v2 如何处理，避免浪费与证据污染

- 原始配置、manifest、观察起点和 Day8/14/21/28/35 结果保持不变；不回填丢失行情，不重写亏损。
- 原采集可以继续提供数据资产；运行状态与保留成本需检查。本轮没有停机或更改保留策略。
- 报告明确标注“冻结费用项口径、非完整账户收益”；旧的完成状态不当作新合同金融有效性证明。
- 新现金流/对冲/风险合同用新 ID；历史合格数据可作 development 输入，但观察过的数据不能变回最终未见验证。
- 正式采用本计划时，更新 `CURRENT_STATE` 和计划导航，保留旧报告并明确新旧权威边界；本计划稿不静默覆盖旧执行合同。
- 仅输出格式或性能等不改变经济语义的修复，经一致性验证可以复用合格原始证据；不能一概重启全部时钟，也不能把实质合同变化说成无影响。
- 已关闭研究族保持关闭；只有实质新增数据、成本或产品条件及明确批准，才讨论新的实验资格。

## 12. 日常推进与检查频率

### 每个实施工作日

开始时列出本日最多三个可验收事项；先处理阻塞经济判断的工作。结束时必须产出代码/测试/报告/决定之一，不能只有“已运行若干小时”。

统一汇报七项：

1. 阶段与原定节点。
2. 新增证据和对应文件/运行身份。
3. 数据健康、金融有效性、经济证据、权限四个独立状态。
4. 昨日未知的问题，今天关闭了几个。
5. 已用工作日、自然等待天数及预算。
6. 当前阻塞、最迟决定时间以及需要谁决定。
7. 下一动作和明确验收条件。

实施者负责实现、测试与证据；用户负责风险偏好、采购/资金预算、产品/账户变更及交易授权。每个门禁需按金融、统计、工程和风险清单交叉复核，不把同一段代码的自检当作独立专家背书。

### 系统检查建议

- 数据健康、缺口、磁盘/保留及账务异常采用轻量监控；频率和告警通道在实施时配置验收。
- 新交割、输入修复、正式门禁或新版本验证时重算完整经济证据；没有新事件不反复运行整套 Full。
- 先 profiling，再按原始内容 hash 做增量解码/索引；全量与增量必须结果一致，完整复核保留。
- 经济观察至少每周作一次预算复核；即时安全异常不等周会。
- 阶段报告读最近完整结果时必须显示评估时点，不能把旧报表当作实时状态。

### 圆桌复盘的触发器

遇到下列任一项，暂停受影响的调参和扩建，先作根因与路线复盘；必要的保护动作和证据保全不暂停：

- 修复破坏其他核心不变量，或同一语义问题在两个修复周期后仍未消除。
- 测试通过但金融反例失败；盈利来自遗漏成本、未来数据或不可能成交。
- 需要扩大风险、改资本分母、放松成本/门槛才能让结果通过。
- D5/D10 或观察预算到期，没有明确新增决策信息。
- 同一机制达到两轮新研究预算或既有更严格失败预算，仍无实质进展。

复盘必须交付：事实、根因假设及反证、可选方案、风险与预算、明确继续/转向/关闭决定。未经决定不继续堆补丁。

## 13. 阶段退出不是一律 PASS/FAIL

| 状态 | 含义 | 动作 |
|---|---|---|
| 合格 | 该阶段的证据与约束满足 | 只进入下一阶段，不自动扩大交易权限 |
| 经济性否定 | 所测试合同不满足经济/风险要求 | 保存负结果，关闭相关搜索 |
| 技术无效 | 核算或数据不可信 | 不计作策略亏损/盈利；修复须有预算及不变量验收 |
| 证据不足 | 尚不能下经济结论 | 在预算节点作继续价值判断，不自动等待 |
| 授权待定 | 需要购买、账户或风险决定 | 完成不受影响事项，受影响路径暂停 |
| 项目暂停 | 当前投入不值得或约束不兼容 | 保留可复用资产，明确恢复所需外部变化 |

项目暂停不是宣称所有策略都不可能盈利；它是当前证据和预算下停止继续投入的决定。

## 14. 启动后的第一批具体事项

按以下顺序进入 D1，不先运行又一次完整收益实验：

1. 建立目标/权限/预算决策清单，确认期权账户模式与逐仓要求是否兼容；未决定前保留原边界。
2. 将复盘中的金融语义反例转成验收用例，先观察现行实现如何失败，明确正确行为。
3. 验收历史数据样例及缺口清单，形成采购或不采购的依据。
4. 在新实验命名空间设计最小现金流、NAV/margin 和持仓生命周期接口。
5. 登记 D5、D10 的绝对复核日期与报告方式；没有实际配置调度前不宣称已自动安排。

最终节奏是：**短工作周期决定值不值得继续；合格历史先排错；自然时间只用于不能替代的迁移与实际执行验证；每段投入都有出口。**
