## 通过条件与连续执行

1. 历史输入必须有可核实的固定版本及当时可知依据。Git author/committer 时间
   单独不足；可用第三方公开事件、历史发布记录或时点明确的原始链状态绑定。
   仅有日期不能自动加一个延迟就认证首发。旧数据保留，缺日不补零。
2. 队列是可检验的库存压力代理，不要求 G0 先证明盈利或每笔退出实际卖出。
   但必须区分验证者数量、名义 ETH、提款、合并／再质押和卖压假设，说明
   代理的局限及什么经济结果会否定它，不能把单位变化作为信号。
3. 拟开发／确认区间须有完整消费审计、容量及可达统计终点。26 完整周最低
   长度、成本和安全要求不降低，不把旧 BTC 或已见 ETH 重新标为独立确认。
4. 如输入成立，连续冻结原单方法单批次 G1 至 G4 的动作、成本、学习／对照
   与一次确认合同，不另问普通步骤。输入不足或两小时／100 次先到即结案，
   不追加数据源采购、第三机制或长期观察来回避本轮裁决。

## 执行边界

新读取含失败请求按次记账，不因换工具漏计；大体积归档每对象不超过 150 MB，
全轮不超过 300 MB。匿名只读第三方公开档案可用于发布时间诊断；不扫描账户、
尝试凭据或规避访问控制。未知访问故障停止依赖步骤，允许不同证据路径诊断，
不无限重试。现有工具优先，无合格输入不先造交易或训练框架。

沿用 `.artifacts/perpetual-g0-restart-20261008/validation-state.json` 的 READY
资料诊断 gate 追加本轮检查，旧历史原件、其他 gate 和旧 G0 结果不改。只发布
必要代码与脱敏结论，main 提交带 `[skip ci]` 并核对实际工作流；原始来源本地
保存。Demo operator reduce-only、候选关闭及 V4 旧失败均不受本授权改变。
