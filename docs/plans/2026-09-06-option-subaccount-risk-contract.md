# 独立子账户期权方案：设计与离线验证合同

状态：用户已同意子账户方案；本轮权限仅为设计及离线验证。它不是新账户、资金或交易授权。

## 1. 已决定的边界

- 以独立子账户作为研究边界；不复用当前逐仓账户，不改原有运行配置。
- 第一版研究 USDT 单币资金、BTC USDT 期权及 BTCUSDT 线性永续对冲，账户模式暂选普通 Cross（[账户 API](https://bybit-exchange.github.io/docs/v5/account/account-info) 的 `REGULAR_MARGIN`）。不引入 Portfolio Margin 的组合抵扣假设，也不假定多币抵押可无成本兑换。
- 实际子账户 UID、实际资金限额仍为空；测试用本金只是合成输入。现有凭据不读取，账户不创建、不切换、不入金。
- 不自动补资，不申请提款/划转能力。任何观测到的负 USDT 钱包或借款都触发离线退出复核，不能视作已成功阻止交易所自动借款。
- 独立子账户不是法律或经济意义上的本金损失保证；在确认平台条款、负余额、自动借款、跨账户权限及尾部平仓行为前，不宣称最大亏损被入金硬封顶。

[Bybit UTA 官方说明](https://www.bybit.com/en/help-center/article/Introduction-to-Bybit-Unified-Trading-Account)列出 USDT Options 的 Cross 支持、自动借款机制，以及账户 MMR 到达 100% 的强平条件。这是模式选择的依据，不是允许逼近强平线的策略阈值。

机器权限合同为 `config/option_subaccount_research_scope_v1.json`：只有 `design`、`offline_validation` 为 true。工具要求精确匹配，改成账号操作或交易权限会拒绝运行。该合同没有接入生产加载链。

## 2. 为什么分离账务与风险

统一账务只负责核对现金流、持仓和估值；账户保证金由独立输入/模型负责。不能用相同一套简化公式同时制造保证金结果和验证结果。

| 层 | 当前实现/规则 | 不能替代的证据 |
|---|---|---|
| 资金与范围 | 单个显式离线 scope，空仓起点，固定合成本金，外部转账一律拒绝 | 真实子账户身份、实际预算与权限 |
| 现金流 | 权利金、期权平仓/交割、永续已实现盈亏、funding、显式费用 | 交易所流水、历史费用口径与原始来源 |
| 估值 | 逐事件现金 + 期权市值 + 永续未实现盈亏；独立报告退出方向 BBO 估值 | 连续真实可成交退出路径、未来平仓费、冲击和尾部流动性 |
| 保证金 | 同检查点外部账户快照，核对 scope、持仓、钱包、USD 权益、IM/MM 与债务 | 历史保证金参数、订单占用、haircut、order loss、交易所模型重建 |
| 判定 | 技术无效、证据不足、离线风险否定或仅账务通过；所有晋级/交易权限 false | 独立经济资格、forward、Demo、实盘批准 |

[钱包 API](https://bybit-exchange.github.io/docs/v5/account/wallet-balance)将账户权益、保证金余额、可用余额及 IM/MM 分开，并以 USD 返回账户级值。因此本工具显式要求 USDT/USD 指数，不把 NAV、margin balance、available balance 当同一指标。IM/MM rate 取自外部输入，不擅自用 `MM / NAV` 重算成交易所公式。

## 3. 当前离线账务语义

- 期权交易数量为有符号 BTC，报价为 USDT/BTC；现金变动为 `-signed_qty * price - fee`。卖出收到权利金后，同时计入负期权价值，不能把权利金直接记成利润。
- 永续开仓只扣费用，不扣整笔名义本金。加仓更新加权成本，减仓实现对应部分盈亏；穿越零仓位时新方向重设成本。
- 每个实际 funding 边界绑定 settlement ID、时刻、符号、当时有符号持仓、结算 mark 和已结算 rate。资金流为 `-position * mark * rate`；额外核对提供的有符号 cash delta。重复、错位、预测 rate 均拒绝。
- 提供的 funding 日历中缺事件会判证据不足。但调用者可以漏提供日历，所以“事件齐全”不证明真实历史 funding 齐全；该缺口保留在所有报告中。
- 交割只接受持仓合约、元数据约定到期时刻和明确交割价类型；按 call/put 内在价值及实际数量记现金。禁止交割后继续交易该合约。输入声明 `official_delivery` 并不等于来源已被独立认证。
- 所有成交为显式 taker 假设，核对方向 BBO、数量、lot 和因果时间。费用字段不可省略；本版本不支持返佣和额外币种费用，不能丢弃它们后继续通过。
- 每条事件附全量持仓估值。缺 mark、未知字段、错币种、重复 ID、混账户、倒序、错误资金流都会拒绝。时间相同的事件按显式 seq 执行；真实结算边界顺序仍需来源验证，不能依靠任意排序生成正收益。
- 提供的检查点之间有超限缺口、退出一档深度不足、缺保证金或期末未平仓，都不能给出完整生命周期通过。
- 给出的收益仅为合成本金/未认证研究输入上的算术值。回撤仅为观察检查点的回撤，不是全路径 MDD；不计算 Sharpe，不声称实际盈利。

[Bybit 交易流水 API](https://bybit-exchange.github.io/docs/v5/account/transaction-log)将现金流、funding、交易费和现金余额分别提供；funding 正值是收入、fee 正值是支出。未来适配器必须按来源统一符号，不可直接混用 execution fee 的方向。本版本尚无私有流水适配器。

## 4. 风险判定边界

测试中的 IM 50%、MM 60%/80%、DD 20% **仅为验证分支的示例参数**，不构成实际账户风险限额，也不覆盖生产阈值。正式限额须由资本、保证金压力、平仓成本和尾部损失共同标定并冻结。

超出示例 IM/MM 或可用余额为负，产生离线风险否定；净值非正、DD 超限、MM 退出阈值、负钱包或借款会锁存退出复核标志。锁存不因后续行情恢复自动清除。

这里的“退出复核”不是发出逐腿市价单。期权平仓和撤掉对冲可能让组合风险反而上升，真实退出需经过整组冲击、腿顺序、订单撤销、部分成交及流动性验证。未知风险时不允许新风险，亦不能伪造可安全退出的结论。

## 5. 结果驱动的下一步

1. **本轮出口：** 权限合同及离线账务内核，经手算与故障反例核对；不启用生产模块。
2. **R2 数据出口：** 固定产品生命周期、连续 BBO/数量、实际 funding/交割、instrument 单位、费用/保证金和来源授权。逐项验收，不用单分钟样例代替。免费来源不足时列清缺项及预算，不自动采购。
3. **R3 完整账务出口：** 把资格合格的原始来源适配成可溯源事件，独立核对账务；构建并校验历史保证金、连续 NAV、尾部/脱锚/断连及组合退出压力。届时再称完整研究账务通过。
4. **R4 经济出口：** 同资本/成本合同的固定基线、未见历史和尾部上界；经济否定则停止该合同，不能用重新挑阈值救回。
5. **之后才进入 forward / Demo：** 仍遵守总计划及独立权限门。账户创建、资金限额、入金和 Demo 启用分别确认；实盘不自动开放。

本轮只是为 R2 定义所需经济输入及准备 R3 的离线内核，不表示越过未通过的 R2 数据门。旧 v2 策略、身份、采集时钟和历史亏损均保持不变。
